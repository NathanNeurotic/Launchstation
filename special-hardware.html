PSX, Deckard & RetroGem

Launchstation adapts to the console it runs on: it hides hardware that cannot exist, shows PSX-only devices on a DESR PSX, offers PC CARD CompactFlash on early Japanese models, and can emit the Game ID signal that a PixelFX RetroGem reads. Always include the exact console model in reports; behaviour that is correct on a fat SCPH with an HDD can be intentionally different on a slim or a PSX.

Hold SELECT while Launchstation starts to override the HDD/ATA, PSX flash/DVR and CF-entry hiding for that boot (iLink visibility is not overridden). Combined with the safe-mode side effect, that is the quickest way to test whether a hidden device is really unsupported.

Deckard PS2 models

On consoles whose ROM version is 2.20 or newer there is no internal expansion-bay HDD, so the Internal HDD (APA) and exFAT HDD cards are hidden. This avoids presenting dead hardware paths as normal choices. USB, MMCE, MX4SIO and the network remain available. On consoles with a PowerPC-type IOP, disc launches also load the XPARAM module, which applies Sony’s per-title compatibility values (CPU delay, data-cache) from a built-in table before the game starts; this is automatic and has no setting.

Sony PSX / DESR

On a DESR console Launchstation exposes PSX Flash (xfrom0:, the internal flash) and PSX DVR HDD (dvr_hdd0:, the recorder disk). iLink is hidden: the PSX’s i.Link port only works with Sony DV camcorders and cannot be used for file transfer or homebrew storage, unlike the port on fat PS2 models before SCPH-50000. Both are file-management devices; the exploit installer recognises the PSX and selects the PSX target. The HDD Manager works but refuses to format the PSX disk. They appear on other consoles only in the SELECT-held recovery boot, where they are not expected to work. See the exploit installer for PSX targets and key requirements.

Early PS2: PC CARD CompactFlash

Launchstation can read a CompactFlash card (or an SD card through a CF bridge) in the PCMCIA slot of early Japanese consoles (SCPH-10000, 15000, 18000 and the same ROM family). The device is PC CARD CF (cf0:). It supports browsing and file management on FAT32/exFAT; launching programs or games from it is deliberately unavailable, and the driver and DEV9 never run together. It has not been verified on a physical console yet. Full details, limits and troubleshooting are on the PC CARD CF page of the Storage & Devices section.

RetroGem Game ID

The PixelFX RetroGem reads a small two-frame signal that Launchstation draws on the video output just before it hands control to a game or program. It is a row of paired pixels along the lower part of the picture that encodes the ID (up to 11 characters, with a checksum); the picture is otherwise black for those frames and then cleared. It is separate from the MMCE “Game ID” command, which selects a per-game memory card on the adapter.

Both switches are under Settings > Launching > Game ID output (also in the classic Advanced settings). If you see brief coloured bars when starting an ELF, the apps switch is on; turn it off if your display adapter does not use it. The signal is only drawn, never required for the launch to succeed. A missing or unrecognised ID simply omits it. Physical RetroGem recognition has not been verified by the project, and a drawn signal is not proof the adapter decoded it.

Dual HDD / ATA

The standard build contains groundwork for two APA units (hdd0:, hdd1:) and two exFAT units (ata0:, ata1:). Unit 1 is hidden by default (Hide HDD1 + ATA1); change it under Settings > Storage & devices. Treat dual-drive operation as hardware-test territory: an enumerated second unit is not proof of working dual-drive operation.

DualShock 3/4 build

A separate “DS” package includes the DS3/DS4 USB and Bluetooth controller drivers. It needs its own console validation with concurrent storage use; the standard package is the better choice unless you need those pads.

Hardware-specific reports

Please include: console model and ROM version (Tools > System information), attached adapters and drives, whether the same device worked in the classic launcher, whether it needs a SELECT-held boot to appear, the exact build hash, and any on-screen message.
