MMCE (SD2PSX / MemCard PRO2)

MMCE is both a storage device and a memory card. Launchstation talks to the adapter’s SD card through the MMCEMAN driver, so you can browse and copy files on it, launch games from it, let Launchstation ask a responding adapter to select the matching Game ID card on launch, and keep versioned backups of its emulated memory cards.

Supported adapters

Adapters that speak the MMCE protocol of the sd2psXtd firmware: SD2PSX, PSxMemCard Gen2 and MemCard PRO2. Launchstation uses the firmware commands as they exist and does not require patched or forked firmware. Other MMCE-capable devices are untested.

Browsing

The device cards are MMCE Slot 1 (mmce0:) and MMCE Slot 2 (mmce1:), one per memory-card port, each checked separately. A card starts Not checked. Selecting it loads the MMCE driver, sends a short presence ping (two attempts) and only then opens the filesystem, so an empty slot is reported as No MMCE storage found without a long wait. A responding adapter reads SD2PSX / MemCard PRO2. Presence does not prove the SD card is healthy; the first directory listing does.

Notes for file work: the adapter has no timestamp-set command (Launchstation skips it quietly after a copy), paths are limited to 254 bytes on the wire, and the name __active_card__.mcd is a read-only virtual file Launchstation reserves against create, rename, delete and truncate. Typical SD layout: mmceN:/MemoryCards/ with numbered, named, GameID and BOOT/BootCard*.mcd card images, plus your own folders such as POPS/ for PS1 VCDs.

One SIO2 bus: MMCE and MX4SIO exclude each other

MMCEMAN hooks the memory-card SIO2 bus. MX4SIO uses the same bus, so loading one while the other is resident resets the IOP (controller and audio are rebuilt automatically). Launchstation will not load the second driver if that reset is refused. The auto-start settings enforce the same rule: enabling MMCE disables MX4SIO and vice versa, and neither can be enabled while you are booted from the other. See Stacks that cannot coexist.

Backup integration

The File Browser offers, inside any mmceN: folder: Back up all MMCE cards… (normal, named, GameID and BootCard images), Back up active MMCE card… (reads the exact firmware-selected image through the virtual __active_card__.mcd), Export active MMCE card as PCSX2 .ps2…, and for a highlighted .mcd Back up selected MMCE card to history…. All write only to your local history folder (WLE-MMCE-Backups), verify the result, skip unchanged cards and never write to the adapter. The full workflow, retention, Google Drive sync and recovery are on MMCE Backup History.

Which card is in use, and switching cards

Inside an mmceN: folder, Which MMCE card is in use? asks the adapter for its card and channel, then confirms the answer by content: it compares the virtual __active_card__.mcd with MemoryCards/PS2/CardN/CardN-C.mcd, or, for BootCard, Game ID cards and stale numbers, with every image under MemoryCards/PS2. The content check is needed because the adapter can keep reporting the old number after its own buttons were used. Two identical images do not count as a confirmed match.

With a numbered card image highlighted (MemoryCards/PS2/CardN/CardN-C.mcd), Make this the active MMCE card… selects it on the adapter, waits up to 15 seconds while the adapter reports busy, and reports success only when number, channel and content all agree afterwards. It sends one command at a time and waits until the adapter reports each one taken, because the adapter keeps only one pending command and does not act on it while the console is writing or a button on it is held. It never uses the combined card-and-channel command, which older sd2psx firmware and MemCard PRO2 lack. This is the only action that changes the selected card, and only when you choose it.

Switching only works between numbered cards. MMCEMAN cannot select a Game ID card by number, and sd2psx and MemCard PRO2 firmware do not leave a BootCard or Game ID card for a card number from the console. So when the adapter is serving a BootCard, a Game ID card or a named card (or its card number does not match what it serves), Launchstation sends nothing and asks you to change cards with the adapter’s buttons first. A game that sends its Game ID can still switch the adapter to that game’s own card afterwards. Not yet tested on a console.

Editing saves inside card images

Card contents… on a card image lists its saves and can copy, move, delete, export and import them, and copy the whole card to a new size; see Card contents. On MMCE it refuses to write to the card the adapter is serving to the console, or to any card when it cannot tell which one that is. Its safety copies go to mmceN:/WLE-Safety/ and resized cards to mmceN:/WLE-Resized/, both outside MemoryCards/, so the adapter never offers them as cards.

Recovery without touching the active card

You can store a verified snapshot on the adapter as a new file in mmceN:/WLE-Recovered/ (Store NEW snapshot on MMCE…), or create an additional selectable card with Install as NEW selectable MMCE card…, which picks an unused MemoryCards/PS2/CardN/ folder and writes CardN-1.mcd. Neither replaces, renames over or activates an existing card. Direct replacement of an emulated card is intentionally unavailable; see the restore protocol for why. If an install is interrupted, inspect the new CardN folder before selecting it.

IGR workflow

Launchstation can be started by OPL’s Exit to (in-game reset) through a small helper, WLE-IGR.ELF. On return it can back up every MMCE card before continuing to Launchstation, the PS2 system menu or an application you choose. Setup, defaults and failure behaviour are on the IGR page.

Neutrino and Game ID card switching

Neutrino has a dedicated mmce backend. Launchstation can also discover a complete /neutrino/ install on the game device or on either memory-card slot. For PS2 ISOs it reads the title ID from the image’s SYSTEM.CNF and, if the MMCE driver is already running or can be started without disturbing other storage, asks responding adapters to switch to that title’s GameID card. It skips any slot that holds the ISO or the Neutrino ELF, never switches an ambiguous alias, and never replaces an active MX4SIO stack for this optional step. A missing Game ID or an adapter error never stops the launch. Details: Game ID, RetroGem and MMCE cards. Disc launches also write the OSD history file on a memory card so an MMCE can follow the game.

Troubleshooting

  1. “No MMCE storage found” but the adapter works as a memory card. The SD card may be missing or unreadable, or the firmware does not provide the filesystem commands. Update the adapter firmware.
  2. Slot 2 card missing after using MX4SIO. MX4SIO owns memory-card port 2 while its stack is active. Opening mc1: or an MMCE slot makes Launchstation reset the IOP back to the card stack, after which the slot is probed again.
  3. Stalls when loading. The driver startup handshake is synchronous; an absent adapter can pause drawing for a moment (about 0.8 s nominal with both slots empty). Report firmware version, slot and whether audio recovered.
  4. Backups say “Set destination”. Choose a backup folder first (Settings > Storage & devices > MMCE backups). It cannot be inside mmceN:/MemoryCards.
