Network & PC Integration

Launchstation has no resident network stack. Ethernet, FTP, the PS2Link host, UDPFS, Google Drive, update checks and clock sync each start their drivers only when you use them.

Trusted local network only
These are homebrew console services, not hardened internet daemons. The built-in FTP server accepts anonymous logins and the PS2Link host accepts any PC that can reach it. Keep the PS2 on a trusted LAN and never forward its ports from the internet. See Network exposure.

Two Ethernet stacks

The Ethernet driver exists in two forms, and only one can be resident at a time. Switching from one to the other resets the IOP, so other devices are detected again the next time you open them.

StackDriversUsed by
ETH (PS2IP)PS2SDK DEV9, PS2IP and SMAP, plus ps2netfs, ps2ftpd and the PS2Link ps2host moduleFTP / Remote access, the host: Network Host device, Google Drive, update checks, Internet clock sync
UDPFSSource-built udpfs_smap (receive-tail and startup fixes), then the prebuilt udpfs_ministack and udpfs_iomanThe udpfs: device, PC-hosted files, Neutrino ISOs served over the network, PC game transfers

Both stacks sit on DEV9. On early Japanese consoles, the PC CARD CompactFlash driver also needs DEV9; while it owns the bus the network stacks refuse to load, and the reverse. Consoles without a network adapter cannot use any of this.

IP configuration

Open Settings > Network to set the IP address, Netmask and Gateway. The defaults are 192.168.0.10, 255.255.255.0 and 192.168.0.1. The ETH stack is configured with all three values; the UDPFS stack is given only the IP address. There is no DNS field.

  • Where it is read from: IPCONFIG.DAT beside the running ELF first, then mc0:/SYS-CONF/IPCONFIG.DAT and mc1:/SYS-CONF/IPCONFIG.DAT (the slot the ELF was launched from is tried first).
  • Format: one line, ip netmask gateway, separated by spaces. Saving rewrites that first line and keeps any later lines in an existing file.
  • Saving: network edits are written to IPCONFIG.DAT (not DASHBOARD.CNF) and follow Settings' Save/Discard prompts.

Legacy Ethernet drivers

Settings > Network > Legacy Ethernet drivers (NET_LegacyDrivers) swaps in the PS2SDK v1.0 DEV9/PS2IP pair preserved from oMrRexD's builds. Try it only if the standard drivers load but the SMAP link never comes up. It takes effect the next time Ethernet/FTP starts, and changing driver families makes Launchstation reset the IOP.

FTP, PS2Link and remote commands

Tools > FTP / Remote access starts the ETH stack, ps2netfs and the FTP server, then shows the active address. The PS2Link host: filesystem loads the first time you open Network Host. While FTP is running, the Home screen also watches for MrRexD-compatible PC commands and game-transfer requests. Details, file formats and the security model are on FTP, PS2Link & Remote Control.

PC game receiver

A PC tool that follows MrRexD's protocol can drop a PS2-RECEBER.TXT job through FTP. Launchstation then switches to UDPFS, copies each listed file from the PC to a staging folder on the internal HDD (ata0:), resumes after dropped connections (up to eight retries per file), renames the finished file into DVD or CD, writes PS2-RECEBER.RES and returns to FTP. It needs a drive at ata0: (the internal HDD or another ATA/exFAT drive). Triangle cancels. See the job format.

UDPFS

Network (UDPFS) appears in the Devices list and in the File Browser. It talks to a PC running UDPFSD and shows UDPFS server not found when none answers. The File Browser's write commands on host: and udpfs: stay disabled unless Settings > Network > Allow writing over the network (NET_HOSTwrite, off by default) is on; that setting does not affect FTP. UDPFS is also an accepted Neutrino ISO backend; see PS2 ISO · Neutrino. Settings > Storage & devices > Start devices automatically > Auto-start network (UDPFS) starts the client at dashboard launch; leave it off if you do not use it.

Features that reach the Internet

Only these features open connections beyond your LAN, and only when you invoke them. All of them use the ETH stack, and all HTTPS uses verified TLS (Mbed TLS 3.6.7).

  • Google Drive backups: OAuth device linking and uploads to Google. See Google Drive Cloud.
  • Check for updates (Settings > Storage & devices > MMCE backups): GitHub release lookup and package download. See Downloads & Releases.
  • Sync PS2 clock from Internet (Settings > Network): SNTP query to 0.pool.ntp.org (UDP 123). It loads PS2IP and the PS2IPS socket RPC server on demand, without starting FTP or netfs services.

Exactly what each one sends is listed in the Privacy Policy.

PC-side cloud relay

The repository also ships an optional Windows helper, windows/cloud-relay, that pulls the WLE-MMCE-Backups history off the PS2 over FTP and copies it to any rclone remote (copy-only, never sync). It suits cloud providers other than Google Drive, or users who prefer to keep credentials on the PC. Start FTP / Remote access first.

Failure isolation

  1. Confirm the adapter and link light, and that the console is not a CF-only early model.
  2. Confirm IP, netmask and gateway on the PS2 and that the PC is in the same subnet.
  3. Start only the one service you need; remember that FTP/Google (ETH) and UDPFS cannot be loaded together.
  4. Test basic reachability from the PC (an FTP login for ETH, UDPFSD discovery for UDPFS).
  5. Only then debug Google Drive, update checks, or higher-level transfer requests.

Native cloud sockets use a 15-second no-progress timeout for connect, TLS handshake, reads and writes. DNS resolution happens in the synchronous PS2IP resolver call and is not covered by that timeout, so a bad DNS setup can still stall until the resolver gives up. Certificate checks use the PS2 clock; if it is badly wrong, HTTPS fails with an expiry error, so fix the date first (or use the clock sync).
