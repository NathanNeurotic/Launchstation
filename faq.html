Frequently Asked Questions

Which package should I download?

APP_LAUNCHSTATION-<build>.zip (or APP_LAUNCHSTATION.psu for a memory card) for ordinary PS2 controllers. Use APP_LAUNCHSTATION-DS only if you want PS3/PS4 DualShock USB/Bluetooth support; it is the same program built with the inherited DS34 drivers and uses the same settings. See Downloads & Releases.

Where did the separate Apps and Devices tabs go?

There are now four top-level tabs: Home, Files, Tools, Settings. The full Applications library is on Home; Files opens the live native File Browser. Devices are reached from the browser root. Current dashboard navigation.

Is there still a classic interface?

No separate one. The dashboard is the only shell: Settings, the File Browser, the HDD Manager, the Text Editor, the exploit installer and the information screens are all dashboard screens. They run the proven wLaunchELF logic underneath, and the classic MISC commands are available under Tools > MISC commands.

Why is an ELF absent from Applications?

The library scans only configured folders. Use Settings > Home & applications > Application library > Application folders..., then Refresh library now. The current default scan roots include mc:/APPS, mc:/BOOT, mass:/APPS and mass:/BOOT, one subdirectory deep; launchable files on other roots may still work directly through Files.

What does SELECT do now?

While in Home > Applications, SELECT cycles Grid, List and Carousel views. The visible top-level tabs are Home, Files, Tools and Settings. See Controls for the current mapping.

Are Neutrino, POPStarter or Ember included?

No. All three are external projects. A PS2 .ISO is handed to Neutrino, a PS1 .VCD to POPStarter, and a PS1 .CUE/.BIN/.EXE in an Ember game folder to Ember. The image format determines the launcher; there is no preferred-core switch, but each core has a Disable switch under Settings > Launching > Disc & image loaders (Off by default).

Must Ember be at /EMBER/ on the device root?

No. The umbrella folder can have any name and location when the supported <umbrella>/games/<Game>/ layout is retained. Its bios.bin is supplied by the user, and ember.elf is either present or staged from the configured Ember directory. USB launches rebuild the storage IOP stack before the final keep-IOP handoff.

Why can two USB devices behave differently?

Enumeration order and logical mount numbers can change. The loader does not assume mass0: is always the same drive. Tools includes an USB unit diagnostics action; an explicit probe can still block inside a synchronous IOP RPC. Do not unplug active media during writes.

Why does the console reboot its IOP when I switch between MMCE and MX4SIO?

The two stacks are incompatible: both use the memory-card ports. Launchstation resets the IOP driver set when you move from one to the other, so expect a short loading overlay.

Can I restore a card directly to MMCE?

Not automatically. Local history or a hashed Drive snapshot can be validated and recovered into a new USB/HDD .mcd file, or stored as a new file on the adapter or installed as a new selectable numbered card on stock sd2psXtd firmware. Direct replacement or activation of the current MMCE card remains disabled. See Verified MMCE recovery.

Does Google Drive run without configuration?

In official release builds, yes: choose Link Google Drive and enter the code at google.com/device; Launchstation's own OAuth client and the Google trust roots are embedded, so no Google Cloud project or setup files are needed. A build you compile yourself has no embedded client unless you provide WLE_GOOGLE_CLIENT_ID/WLE_GOOGLE_CLIENT_SECRET at build time or a custom client in WLE-CLOUD.CNF. Drive is optional either way: local backup is usable without linking, and cloud sync after IGR is off by default. It needs a wired network. See Google Drive.

How are rolling releases published?

The latest packages are published after the verified master-build workflow: tests, both builds, variant and toolchain checks, loader layout and ZIP/PSU verification must pass first, and the latest tag only ever moves forward to a descendant commit. The native updater requires matching verified app packages and preserves existing sidecars. Compile/CI success does not guarantee real-PS2 hardware acceptance.

How does the in-app updater decide an update is safe?

It asks GitHub whether the release commit is a descendant of your build, checks the downloaded package against GitHub's published SHA-256 digest, validates the ELF, and only then swaps it in, keeping <name>.ELF.BAK. A release that is older, divergent, or cannot be verified is never installed automatically. Details in Install & Update.

Which languages are supported?

English, Spanish, Italian, French, German, Polish, Portuguese, Brazilian Portuguese and Hungarian (Settings > System > Language). Dashboard navigation, Settings labels, common actions and transfer progress are translated; file names, paths and application metadata keep their original text and some extended help is English only. An external .LNG file can override the same message IDs.

How many themes are there, and can I use my own wallpaper?

There are 18 built-in theme presets, plus full custom colors, fonts, icons, clock and artwork. A 4:3 PNG (640x480 or 320x240) works as a static wallpaper. See Themes.

My console forgets the time. Can Launchstation help?

Yes, partly. Settings > System > Set software clock... keeps a saved checkpoint and advances it while Launchstation runs; Settings > Network > Sync PS2 clock from Internet can write the hardware RTC. Time while powered off is unknown without a working RTC. Save with Settings changes > Save current clock before powering off.

Can I build it myself?

Yes. Releases are built with the PS2BUILD SDK and its LLVM/Clang toolchain; a GCC build is available for comparison with PS2BUILD_TOOLCHAIN=gcc. The old Makefile build was retired on 2026-10-26; PS2BUILD is the only build path. See the developer notes and the repository README.

Is there an offline documentation/wiki copy?

Yes. The site generator produces HTML, styles, scripts, search index and a ZIP archive. Read the wiki/guide index or run python3 docs-site/build.py --out build/docs --zip build/Launchstation-Documentation.zip.
