MMCE Backup History

Versioned, verified backups of your MMCE memory-card images, stored away from the adapter, with optional Google Drive copies and recovery that never overwrites an active card.

Set a destination first

No backup folder is chosen by default. Go to Settings > Storage & devices > MMCE backups > Backup folder and pick the parent folder (USB, exFAT HDD, internal HDD…) in which WLE-MMCE-Backups will be created. Until then the page reads Set destination and automatic IGR backup reports “no MMCE backup destination configured”. The folder cannot be inside mmceN:/MemoryCards. Changing it leaves old history where it is, and you must reinstall the IGR helper because the path is embedded in it.

Local history

For every card image found under mmce0:/MemoryCards and mmce1:/MemoryCards (numbered, named, GameID and BootCard images, to a depth of twelve folders) Launchstation keeps a history folder:

<backup folder>/WLE-MMCE-Backups/
└── mmce0/
    └── PS2/Card1/Card1-1/            one folder per card image
        ├── WLE-20261026-101500.mcd   one file per kept version
        └── WLE-20261026-174200.mcd

Each snapshot is written as <name>.PART, compared back against the source, then published with a same-folder rename. An interrupted copy therefore never looks like a finished .mcd/.ps2 history entry and is never uploaded to Drive; an existing .PART is not reused. Retention runs only after a successful publish and never prunes on a failed export, comparison or rename. Backups per card keeps the newest 1–99 versions (default 10); 0 keeps every version. Backup format is .mcd (native, byte for byte; default) or PCSX2 .ps2, which adds ECC/spare bytes and is verified after conversion.

Skip unchanged cards

Before adding a history entry Launchstation compares the card with the newest snapshot of the same format. If it is identical, nothing is written and the summary counts it as unchanged. For the native format the comparison happens before any write.

The automatic backup after IGR and the status scan decide this from a fingerprint instead of reading the whole card: a SHA-256 of the card’s superblock and every directory entry (folders, file sizes, dates and locations, a few hundred KB). Each history copy gets a small <copy>.FP file holding it. History without one is compared in full once and then gets one. The contents of B?DATA-SYSTEM are left out, because the PS2 and OPL rewrite its history file when a game starts, which used to make every played card look changed.

A fingerprint cannot see a save rewritten in place at the same size while the console clock is stuck or reset, because its date does not change. A match is therefore trusted for at most 8 backups in a row; the next one compares every byte and restarts the count. Back up all MMCE cards (Tools and File Browser) and the safety copy taken before a recovery always compare every byte.

Per-save versions

With Settings > Storage & devices > MMCE backups > Per-save versions on (default Off), every backup also keeps each save on the card as its own .psu file, so one game’s history can be kept or restored without the rest of the card:

PS2/Card1/Card1-1/
├── WLE-20261031-101500.mcd
└── WLE-Saves/
    ├── BASLUS-21050SAVE/
    │   ├── WLE-20261026-174200.psu   named after the card copy it came from
    │   └── WLE-20261031-101500.psu
    └── SOURCE.TXT                    the card copy last done without errors
  • The saves are taken from the card’s newest verified history copy, never from the live MMCE card, so turning this on costs no extra adapter reads.
  • A new .psu is kept only when the save’s bytes differ from the newest one already in its folder. A card that did not change reads nothing more: SOURCE.TXT already names its copy.
  • Each .psu is written as .PART, read back and checked against what was meant, then renamed; an existing file is never replaced. A failure is counted in the summary as saves failed and the next backup tries that card again. The card’s own history is not affected.
  • Backups per card also limits the versions kept per save (0 keeps all); the oldest go first and the newest is never removed.
  • The console’s own B?DATA-SYSTEM folders, saves that hold sub-folders and saves larger than 8.5 MB are not kept. A save whose name uses characters other than letters, digits, -, _ and . gets a folder with those replaced and a short hash added, so two saves never share one.
  • To put a version back, open its folder with Save library here… (File Browser) or use Card contents > Import .psu… on a card image; both take a verified safety copy of the card first (see Saves).
  • With Google Drive linked the WLE-Saves folders are uploaded with the cards, and Browse cloud history… can download a single version (Google Drive).

Not yet tested on a console.

Verification matters

A copy only counts after it has been read back and matched. Failures are reported per card (failed in the summary) and automatic steps such as the cloud upload do not run for a card that failed.

Manual backups from the File Browser

Inside an mmceN: folder the options menu offers Back up all MMCE cards…, Back up active MMCE card… (the exact firmware-selected image), Export active MMCE card as PCSX2 .ps2… and, with a .mcd highlighted, Back up selected MMCE card to history…. Any .mcd anywhere also offers Back up .mcd… (verified byte-for-byte copy) and Export as PCSX2 .ps2…; a .ps2 offers Convert to no-ECC .mcd…. None of them writes to an emulated card.

The same folder also offers Which MMCE card is in use? and, on a numbered card, Make this the active MMCE card… (see MMCE). To change the saves inside a card image, use Card contents; every change there starts with a verified safety copy of the whole card.

Sync all cards

Settings > Storage & devices > MMCE backups > Sync all cards scans both MMCE units, creates history only for changed cards and summarizes new / unchanged / failed. If Google Drive is linked, pending local history is uploaded afterward. The page also shows status rows: cards (Locally backed up, N pending, N scan errors, No cards, MMCE unavailable), the IGR helper (Current, Outdated, Not installed, Partial / mixed) and Google (Linked / Not linked). These are read-only scans.

Automatic sync modes

The single Automatic sync control has three modes: Off, Local backup (default) and Local + Google Drive. It applies when OPL returns through WLE-IGR (see IGR). The Drive mode needs a linked account and stays off until you pick it.

IGR helper control

The same page exposes install / update / remove of the verified WLE-IGR.ELF helper (also Tools > OPL IGR automatic MMCE backup) and the After IGR, open destination.

Non-destructive local recovery

  1. Recover to a new .mcd. In Settings > Storage & devices > MMCE backups > Recover saved card image… choose a snapshot from your local history, or highlight a complete .mcd/.ps2 in the File Browser and choose Recover as new .mcd…. Launchstation validates the card image, asks for a USB/HDD folder, writes a .PART file, reads it back and publishes a new RECOVER-###.mcd. Existing files and MMCE cards are never replaced or activated.
  2. Store a NEW snapshot on the adapter. For a local USB/HDD .mcd/.ps2, Store NEW snapshot on MMCE… creates and verifies mmceN:/WLE-Recovered/RECOVER-###.mcd (staged as .PART; if the adapter’s rename fails but the staged file is intact and the final name free, a separate read-back-verified copy is used). The folder is a holding area the adapter does not mount.
  3. Install as a NEW selectable card. Install as NEW selectable MMCE card… (source: a completed local snapshot or a WLE-Recovered image) selects an entirely unused MemoryCards/PS2/CardN folder, writes and verifies CardN-1.mcd, and leaves card selection unchanged. It never replaces an existing numbered, BootCard or GameID image. If rename is unsupported the verified-copy fallback cannot guarantee power-loss-atomic publication: do not select a failed or interrupted new card until you have inspected that folder.

All three work on the unchanged sd2psXtd firmware; no custom protocol is involved.

Browse and recover remote backup history

In Tools > Google Drive backups > Browse cloud history… explore the app-created WLE-MMCE-Backups folder on Google Drive in pages of twelve. Selecting a snapshot that has an uploaded SHA-256 downloads it to a NEW RECOVER-CLOUD-###.mcd on USB/HDD after the complete download’s SHA-256 matches and the card image validates (PCSX2 snapshots are converted where needed). Drive history and emulated cards are never modified.

Cloud is additive

Google Drive upload runs after the verified local backup and is copy-only (it never deletes local or Drive history). A cloud failure does not invalidate the local entry. Setup and privacy: Native Google Drive Cloud Backup.

Troubleshooting

  1. “MMCE unavailable”. The driver could not start (wrong stack, reset refused, no adapter). Open an MMCE card from Files first.
  2. Cards are backed up again every time. Native .mcd history compares against the newest native snapshot; switching format means the first run in the new format writes a fresh entry.
  3. History folder missing after moving the backup folder. Old history stays in the old folder; move it manually if you want one tree.
