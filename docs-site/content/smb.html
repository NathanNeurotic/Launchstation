Network Shares (SMB)

The Network (SMB) device (smb:) opens shared folders on a Windows PC, a Samba server or a NAS over SMB2 or SMB3. An older server that only speaks SMB1 is a folder in the same device (it opens as smb1:/). Shares are saved at the end of Launchstation’s own settings file, LAUNCHSTATION.CNF; an old SMB2.CNF is still read until you first save a share. Not yet tested on a console.

What you need
  • A console with a network adapter (or built-in Ethernet) on the same LAN as the server.
  • A shared folder on the server, and an account that can open it.
  • An IP address for the PS2 (Settings > Network), and Legacy Ethernet drivers off.
  • At least one share, added in Settings > Network > SMB shares (or as text, below).

How it works

Nothing touches the network until you open the device. The first time, Launchstation starts the network with the address in IPCONFIG.DAT, loads the SMB driver and connects every saved SMB2/SMB3 share. smb:/ then lists one folder per connected share, named by its NAME: smb:/PC, smb:/NAS. An SMB1 share is listed there too, by its NAME; opening it goes to smb1:/, the top of that one share, and Back returns to smb:/.

A share that does not connect is left out of smb:/, and the browser says why (for example PC (line 7): Could not connect: check the address, share, user name and password). Opening the device again tries the failed shares again, at most every 30 seconds, because an unanswered connect can take that long. When no share is connected, the share list is read again first, so a corrected file is used without restarting.

When at least one share connects, the browser and the device card show how many are connected, not which one failed. If a share is missing from smb:/, check its address, share name, user name and password in Settings > Network > SMB shares, then open smb: again to retry it. A file changed on a PC while another share is connected is read again after a restart, or after opening it once through Settings > Network; either way a share that is already connected keeps its old address and credentials until the console restarts.

Where shares are saved

The shares are the blocks after a line reading exactly # SMB shares, at the end of LAUNCHSTATION.CNF. The share editor writes them there, and Edit shares as text opens that file in the text editor (edit only the blocks after that line; the settings above it are written again from the running Launchstation). SMB2.CNF, which other launchers also read, is never written.

While LAUNCHSTATION.CNF has no # SMB shares line, Launchstation reads the first SMB2.CNF it finds. The first share you save (or the first time you edit the shares as text) copies its shares across:

  1. beside the running ELF (for example mc0:/APPS/SMB2.CNF for mc0:/APPS/BOOT.ELF);
  2. SYS-CONF/SMB2.CNF on the memory card Launchstation was started from;
  3. SYS-CONF/SMB2.CNF on the other memory card.

That is where IPCONFIG.DAT is looked for too. In both files each line is KEY = value. Each share is the group of keys that ends with its URL, so URL comes last in each group.

KeyValueLongest (bytes)
NAMEThe share’s folder name in smb:/. Required, unique (in any case), no / \ : * ? " < > |31
USERNAMEAn account on the server31
PASSWORDThat account’s password31
VERSION2 (default: SMB2/SMB3, also 3, SMB2, SMB3) or 1 (SMB1, also SMB1, NT1)
PLAINTEXTSMB1 only. 1 lets a server that asks for a clear-text password have it; 0 (default) refuses such a server. See below.
URLsmb://<IP address>:<port>/<share>; give the port, 445 for most servers255
  • Keys can be in any case. Spaces and tabs around a value are removed, so a password cannot start or end with a space.
  • Lines starting with # or ; are comments. A line without = is skipped; the rest of the file is still read. Unknown keys are ignored.
  • A value that is too long is not cut short: the share is refused, and the browser names the share, its line and the key. Lengths are in bytes; each ASCII character is one byte.
  • If the only VERSION = 1 share is refused this way, it is not listed in smb:/: correct it and open the device again.
  • Use the server’s IP address. SMB1 requires one; for SMB2/SMB3 host names are untested.
  • The user name goes in USERNAME, not in the URL. A path after the share name is ignored: the share’s folder opens at the top of the share.
  • Up to 8 shares are read. Only one SMB1 share can be used, because the SMB1 driver keeps a single connection.
# A shared folder "PS2" on a Windows PC, as smb:/PC
NAME = PC
USERNAME = player
PASSWORD = secret
URL = smb://192.168.0.10:445/PS2

# The "games" share of a NAS, as smb:/NAS
NAME = NAS
USERNAME = ps2
PASSWORD = n4s-pa55word
URL = smb://192.168.0.20:445/games

# An old server that only speaks SMB1, as smb:/OLDBOX (smb1:/)
NAME = OLDBOX
VERSION = 1
URL = smb://192.168.0.30:445/PS2SMB

The shares are read at startup, which reads no network.

What you can do

  • Browse, copy, rename, make and delete folders inside a share. A listing that fails part-way is an error, not a partial list. File dates and attributes are not set on the server (the SMB2 driver has no way to).
  • Nothing can be made in smb:/ itself: it only lists the connected shares. Rename works inside one share.
  • Launch an ELF from a share, as from udpfs:. Not yet tested.
  • PS2 ISO games through Neutrino: install the latest complete upstream nightly on a local device, then open the ISO. Launchstation maps the selected share and credentials into config/bsd-smb.toml and launches -bsd=smb -dvd=smb:<path within the share>. Neutrino resets the IOP and opens its own session. See Neutrino SMB.
  • POPStarter VCDs and Ember images: Launchstation has no SMB handoff for these cores.

Stack rules

  • SMB uses the same Ethernet stack as FTP, PS2Link and Google Drive, so they can be used together. UDPFS uses a different one: opening SMB after UDPFS (or the other way) resets the IOP, and copying between udpfs: and smb: is refused (“Incompatible drivers to perform action”).
  • SMB uses DEV9: it does not start while PC CARD CF owns the bus, and copying between SMB and PC CARD CF is refused.
  • SMB needs the current Ethernet drivers. With Legacy Ethernet drivers on, the device says so and does not start.
  • The SMB2 driver uses about 140 KB of IOP memory once loaded.

Troubleshooting

  1. “No shares”. Add one in Settings > Network > SMB shares, or put an old SMB2.CNF beside Launchstation or in mc0:/SYS-CONF/ and restart.
  2. “Could not connect”. Check the server’s IP address, the share name, the user name and password, that the PS2 is in the server’s subnet, and that the server allows SMB2 (Windows: the share is reached with an account that has a password).
  3. SMB1: “Server does not speak SMB1” or “Server did not answer”. Windows 10 and later turn SMB1 off; use SMB2 (leave VERSION out) unless the server is really SMB1-only.
  4. SMB1: “User name or password refused” also appears when the server only accepts clear-text passwords. Launchstation does not send a password in the clear unless the share has PLAINTEXT = 1. Better: turn on encrypted passwords on the server (Samba: encrypt passwords = yes). With PLAINTEXT = 1, anyone on the network who can see the traffic, or pose as the server, can read the password, so use it only on a network you trust and with a password used nowhere else. A server that takes encrypted passwords still gets the encrypted form.
  5. “The SMB driver could not be loaded”. The IOP may be short of memory with many other drivers loaded; use Tools > Reboot IOP and open the share first.
