Saves, PSU & Timestamp Tools

Launchstation keeps the classic memory-card and save toolbox of the LaunchELF family: browse saves by title, copy them between devices, wrap them in .PSU containers, mount virtual memory cards, back up whole card images, and reorder folders on a card by editing their dates. Destructive actions on exploit folders are explicitly confirmed.

Treat saves as saves, not as PC folders

A PS2 save is a folder with an icon.sys, icons and a PS2-specific timestamp and attribute set. Copying it as plain files to a PC disk can lose that metadata. Use Create PSU to move a save onto USB/HDD/network storage, and Extract PSU to put it back.

Browsing saves by title

In the File Browser, Show (options menu) switches between File names, Names and details, Game titles and details and Game titles; titles come from the save’s icon.sys for PS2 saves, PS1 saves and .PSU files, on any device. A valid two-line icon.sys title keeps its line separation. Japanese titles are drawn with the optional ELISA100.FNT font when it is present; without it they are transliterated. Create folder icon… writes an icon.sys for a folder so that it shows a title on the console.

PSU create and extract

The paste command is labelled by what it will do, so the direction is never ambiguous:

  • Create PSU appears when the clipboard holds folders copied from a memory card or virtual card (mc0:, mc1:, vmc0:, vmc1:) and you paste into a folder on any other device. Each save becomes one .psu file.
  • Extract PSU appears when the clipboard holds only .psu files; pasting extracts them into the destination (normally a memory card or a VMC).

Three switches under Settings > System > Memory card backup files control PSU names: add game ID and title to names, add date to names and never overwrite existing files (turning this on also turns dated names on; turning dated names off turns it off). Moving a protected folder (Cut) asks for confirmation first.

Copying saves and files

Ordinary copy, move, rename and delete work on every writable device, with progress, readable errors and (for slow memory-card and VMC operations) small transfer chunks. Replacing an existing file follows the upstream behaviour: the old destination is removed, a new file is created, and the data is copied. If that copy fails after the removal, the old file is not restored, so copy important data elsewhere first. Same-path paste is blocked so a source cannot delete itself. Cut deletes the source only after the copy succeeded. MMCE cannot set timestamps, so that step is skipped after a copy to it.

Virtual memory cards

Highlight a .BIN, .VMC, .MC2 or .PS2 card image and choose Mount as vmc0: or vmc1:. The mounted card appears as Virtual MC 0/1 in the device list and its saves can be copied, deleted or exported with the normal tools. Mounting into a slot replaces whatever was mounted there; the driver is loaded on demand. A VMC image used by Neutrino or POPStarter is managed by those programs, not by this dialog.

Card contents: saves inside a card image

Highlight a .mcd, .ps2, .bin, .vmc or .mc2 card image on any device, including an MMCE card, and choose Card contents…. It lists every save with its icon.sys title (Japanese titles included), file count and size, plus the card’s free space. The image does not need to be mounted.

ActionWhat it does
Copy to another card…Copies the save into another card image.
Move to another card…Copies, reads the copy back, and only then deletes the save from this card.
Export as .psu…Writes the save as a .psu file.
Delete from this card…Removes the save.
Import .psu…Adds a save from a .psu. The file is fully checked before anything is written.
Copy to a new card of another size…Makes a new 8, 16, 32 or 64 MB card image holding every save. The source card is only read and no existing file is overwritten. The finished card must list exactly the source’s saves, or the new file is removed. MMCE results go to mmceN:/WLE-Resized/, ready for Install as NEW selectable MMCE card….
Split into Game ID cards…Makes one card per game, each holding that game’s saves, in the <ID>/<ID>-1.mcd layout MMCE devices use for Game ID cards. See Game ID cards.

Every write follows the same steps:

  1. On MMCE, refuse the card the adapter is serving to the console right now. When Launchstation cannot tell which card that is, it writes to none.
  2. Check the name and free space with the card opened read-only, so a refusal costs nothing.
  3. Make a verified safety copy of the whole card in a WLE-Safety folder beside the image (mmceN:/WLE-Safety/ for MMCE). The newest 10 per card are kept.
  4. Write, then close, reopen and read the save back.

The writer stores the data and folder first, then the card’s allocation table, then makes the change visible with one 512-byte page. Host tests cut the power before every single write and check that the card still opens and no other save changed.

Limits and status

PCSX2 .ps2 cards and saves with sub-folders are read-only here. Nothing is written while a VMC is mounted as vmc0: or vmc1:, because the VMC driver keeps its own copy of the card’s tables; unmount it first. Cards with more than 250 saves list the first 250, still accept copies and imports, and cannot be copied to a new size. This is not yet tested on a console or checked against Sony’s memory-card driver; keep a PC copy of your cards until it is.

All saves here: every card in a folder

In a folder on USB, HDD, MMCE or the network, open the folder menu and choose All saves here…. Launchstation reads every card image (.mcd, .ps2, .vmc, .mc2, .bin) in that folder and in the folders directly inside it, and lists all their saves together. In mmceN:/MemoryCards/PS2/ that is every card on the adapter. Each row shows the save’s title and, underneath, the card it is on, such as Card3/Card3-1.mcd: BASLUS-21050, 120 KB. The list is sorted by title, and copies of the same save on different cards sit together even when one copy has lost its icon.sys.

Choosing a save opens the same actions as Card contents on the card it is on (copy, move, export as .psu, delete), with the same safety copy, read-back and refusal of the card the adapter is serving. The list is read again after each action. Until you use one, nothing is written.

  • Launchstation’s own WLE- folders (safety copies, resized, new and Game ID cards) are skipped, so their copies do not repeat every save.
  • Files larger than a 64 MB card are not opened; files that are not card images are counted in the subtitle.
  • Up to 64 cards and 1000 saves are listed; a longer list says it was shortened.
  • One save at a time: selecting several saves for one batch copy, move or delete is not in yet.
Status

Not yet tested on a console.

New blank card

In a folder on USB, HDD, MMCE or the network, open the folder menu and choose New blank card…, then a size: 8, 16, 32 or 64 MB. Launchstation writes an empty PS2 card image named Blank-8MB.mcd (or Blank-8MB-2.mcd and so on), formatted with the PS2’s standard layout and timestamped from the console clock. It then reopens the file and checks it: the right size, no saves, every cluster but the root free. If anything fails, the unfinished file is removed. It only ever creates a new file. On MMCE the card goes to mmceN:/WLE-New/, outside MemoryCards/, ready for Install as NEW selectable MMCE card…. The action is not offered on memory cards and VMCs, which are too small to hold a card image.

Status

Not yet tested on a console. Whether the sd2psx and the PS2 accept the 16 to 64 MB layouts is still to be confirmed.

Game ID cards

sd2psXtd-style MMCE devices can give each game its own card: when a game starts, the adapter serves MemoryCards/PS2/<ID>/<ID>-1.mcd for that game’s serial, such as SLUS-21050. To move an existing card to that layout, open it with Card contents… and choose Split into Game ID cards….

  • The Game ID comes from each save folder’s name: BASLUS-21050… belongs to SLUS-21050. System folders such as BADATA-SYSTEM, PS1 saves and folders not named after a serial are left out and counted in the result.
  • Each game gets a new card with the source card’s identity. It starts at 8 MB and moves up a size only if that game’s saves do not fit. Every card is built as <ID>-1.mcd.PART and gets its final name only after it reads back with exactly that game’s saves, so an interrupted split never leaves a half-filled card that looks finished. On a network share that cannot rename files, the finished card is copied with verification instead, and its .PART is removed only after that copy. A game folder that still holds a .PART is treated as unfinished and never reused: delete that folder and split again.
  • The card is named after the serial in the save folder’s name. A game that saves under a different serial than the one it boots from (some multi-disc games and reprints) will not be matched by the adapter; install its card as a numbered card instead.
  • The source card is only read. A game that already has a card in the output folder is skipped, never replaced.
  • On MMCE the cards go to mmceN:/WLE-GameID/<card>/<ID>/, one folder per source card, outside MemoryCards/. Highlight one and choose Install as MMCE Game ID card…: it copies the card to MemoryCards/PS2/<ID>/, verifies it and publishes it the same way as Install as NEW selectable MMCE card…, and only when the adapter has no folder for that game yet. Install before starting the game, because the adapter makes an empty card for a game it has none for.
  • Elsewhere the cards go to a <card>-GameID folder next to the source card. Copy each <ID> folder into MemoryCards/PS2/ on the adapter’s SD card.
Status

Not yet tested on a console. To confirm: that the adapter serves these cards as described, including for games it files under another disc’s serial.

Card image backup and conversion

  • Back up .mcd… – verified byte-for-byte copy of a card image.
  • Export as PCSX2 .ps2… – adds ECC bytes and verifies the copy.
  • Convert to no-ECC .mcd… – strips PCSX2 spare bytes from a .ps2 and verifies it.
  • MMCE-specific history, recovery and install-as-new-card actions are covered on MMCE Backup History.

Timestamp tools: Folder dates

The OSD and exploit launchers list memory-card folders in date order, so the date is how you order them. Select a folder in a memory-card root (or in hdd0:/__common/) and choose Folder dates… (“order the saves”):

ModeEffect
Manual EditPick a folder, then edit its date and time field by field; the list reorders live.
A → Z / Z → AGives every eligible folder consecutive timestamps in alphabetical (or reverse) order.
SAS TimestampsEncodes each folder name into a timestamp so the console lists them by category: APP_, APPS, PS1_, EMU_, GME_, DST_, DBG_, RAA_, RTE_, plain names, SYS_, ZZY_, ZZZ_. Well-known names are mapped (for example BOOT, EXPLOITS, OPL, NEUTRINO, RESTART, POWEROFF).
Set *Tuna DateOnly for a selected folder in a writable memory-card root: sets the reserved date that makes OpenTuna-style exploit folders sort correctly.

Automatic modes leave game-save folders alone (names of the form BxXXXX-12345), give any folder with “TUNA” in its name the reserved *Tuna date, show a progress bar and report how many timestamps changed or failed. On a memory-card root the *Tuna date range is reserved so other folders never collide with it. On hdd0:/__common/ the same tools work without that reservation.

Exploit-folder protection

Launchstation recognises these top-level folders and protects them on memory cards (mc0:, mc1:) and on the PSX flash (xfrom:):

  • System-update exploit folders BIEXEC-SYSTEM, BAEXEC-SYSTEM, BEEXEC-SYSTEM, BCEXEC-SYSTEM. The one matching your console’s region (or BIEXEC-SYSTEM on a PSX) is “for this console”; the others are “for other region consoles”.
  • BXEXEC-OPENTUNA, OPENTUNA, FUNTUNA and FORTUNA (reported as a generic exploit folder).

In the dashboard File Browser, Delete, Cut, pasting into, creating a folder or icon inside, and similar changes ask for confirmation with a “Caution: Exploit folder” message. Rename of a protected folder is refused outright (“This system folder cannot be renamed from here”). The guard exists because a routine rename or delete can turn a bootable exploit card into an unbootable one; a confirmed delete still happens. To install or replace exploits use the exploit installer.

Troubleshooting

  1. Create PSU is missing. The clipboard must contain folders from mc/vmc, and the destination must not be a memory card.
  2. Save titles show file names. Titles need a valid icon.sys; switch Show to a title mode.
  3. Folder dates do nothing. The command is available only in memory-card roots and hdd0:/__common/.
  4. Card full / copy error. The error message includes the numeric driver code; report it with the device pair (for example UDPFS to mc0:).
