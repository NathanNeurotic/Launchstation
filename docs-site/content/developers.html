Developer Notes

The repository uses structural contracts plus a real PS2 toolchain build to stop “looks plausible” changes from silently breaking hardware paths.

CI layers

  • Python regression contracts for settings, navigation, device state, dashboard layout, MMCE/cloud and launch paths.
  • ps2build SDK install/verification.
  • Mbed TLS PS2 cross-build for native cloud.
  • Full Launchstation EE/IOP compile and link.
  • Embedded-loader low-memory layout validation.
  • Artifact packaging and SHA-256 output.

Optional DS34 controller build

The standard build uses wired PS2 pads. To build the inherited PS3/PS4 USB/Bluetooth controller option, run python scripts/configure_ds34.py, then ps2build build -c .ps2-ds34.yaml -o build-ds34. The generated root configuration selects pad_ds34.c, the EE client libraries and both embedded DS34 IOP drivers. CI builds both variants and checks their linked symbols. Release packages include Launchstation-DS34.ELF separately. The native updater currently selects the standard executable, so update DS34 installations manually. Controller and storage coexistence still require console testing.

External-core architecture

POPStarter and Neutrino are independent handoffs layered over shared device/path helpers. Neutrino adds a dedicated keep-IOP path because quick-boot consumes the mounted backing store. The generic normal-ELF reset preference therefore cannot accidentally reset an ISO launch.

Demand-loaded network/device stacks

The dashboard attempts to keep boot fast by not bringing every driver online immediately. A device's Not checked state is a valid pre-probe state, not an error. Features that need networking load it when entered.

Documentation architecture

docs-site/content/*.html stores authored fragments. docs-site/build.py applies the common OPL-inspired shell, creates the search index, validates internal links and builds the offline ZIP. Generated Pages output is deployment data, not the source of truth.

Release behavior

Ordinary pushes keep short-lived Actions artifacts. A deliberate latest publication is explicit. The same build job produces the offline documentation archive so the website and downloadable docs stay in lockstep.
