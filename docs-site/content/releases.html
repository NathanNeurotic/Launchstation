The loose ELF downloads are the same packed executables that are inside the packages; the sidecars (WLE-UPDATE-CA.PEM for HTTPS update checks, BGM.ADP for music) are optional for running but not included with a loose ELF. Each package contains four files: the packed ELF plus title.cfg, WLE-UPDATE-CA.PEM and BGM.ADP. ZIP and PSU payloads match. Every ZIP name ends with the build number (the commit count, for example APP_LAUNCHSTATION-284.zip), so a download always says which build it is. Take the standard package unless you want PS3/PS4 DualShock USB/Bluetooth support, which the -DS package adds. See Install & Update.

How the rolling release works

  • There is a single moving release, tagged latest and titled "Launchstation Rolling <build> - <date> (<commit>)". It is marked as GitHub's Latest release and is not a pre-release.
  • Every push to master runs the full Automated-Build workflow: host regression tests, standard and DS34 builds with PS2BUILD LLVM/Clang, controller-variant and Clang-only object checks, the embedded loader memory-layout check and ZIP/PSU verification.
  • Only after all of that passes are the eight assets (four packages and four ELFs) uploaded, downloaded again and byte-compared, and the latest tag moved to the tested commit. The tag is never moved to a commit that is not a descendant of the previous one, and a build superseded by a newer master commit is skipped.
  • Pull requests build and test but never touch the public release.
  • A documentation-only change also produces a new rolling build, so a new commit hash does not by itself mean the runtime changed.
  • The in-app updater downloads from this same latest release, so the download URLs stay stable: https://github.com/NathanNeurotic/Launchstation/releases/download/latest/APP_LAUNCHSTATION.psu and the other fixed names (the DS PSU and the four ELFs). The ZIP names change with each build, so link the release page for those; the previous build's ZIPs are removed once a new build is published.

Verify a download

GitHub shows a SHA-256 digest for each release asset, and the in-app updater compares against that digest before installing. To check by hand, run sha256sum on the file you downloaded, for example sha256sum APP_LAUNCHSTATION-284.zip (use your build number; shasum -a 256 also works), and compare. The release notes list the build's commit and workflow run.

  • Build toolchain: release ELFs are built with the PS2BUILD LLVM/Clang toolchain; CI rejects non-Clang objects in release ELFs.

  • File operations: ordinary paste follows upstream R3Z direct-overwrite behavior; copy/delete popups show the file name, remaining size and a readable failure reason.
  • Navigation: wrap-around list navigation that keeps the selection visible; offscreen carousel cards are skipped.
  • Neutrino: menu audio stays active until launch is committed; optional per-game profiles via Save for this game.
  • Retained: verified software-clock saves, lazy storage loading, MASS display names, dashboard free-space display and power-off service initialization.

Notes

The -DS packages enable inherited PS3/PS4 controller support; standard packages keep the standard PS2 pad driver. CI success and package integrity do not replace real hardware validation. If a new rolling build regresses on your console, keep a known-good baseline (or the .BAK the updater leaves) and report console model, source hash and reproduction steps. The 2026-10-08 USB-tested baseline is kept as a separate release.
