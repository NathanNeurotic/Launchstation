Dashboard

Launchstation is a single dashboard shell with four top-level tabs: Home, Files, Tools and Settings. The application library lives under Home, Files is the real native File Browser, and every former classic screen (Settings, HDD Manager, Text Editor, exploit installer, information screens, file pickers and dialogs) is drawn inside the same frame.

What was verified
This page is written against the current source (dash_main.c, dash_home.c, dash_apps.c, dash_tools.c, dash_settings.c). Behaviour that depends on a particular console, TV or storage device cannot be proven from the source and is called out as such. See Controls for every button, Settings for every option and Configuration for the files the dashboard writes.

Screen anatomy

  • Header: the four tab icons with L1 and R1 badges at each end of the strip, and the clock/date on the side (see clock options). The selector slides smoothly between tabs.
  • Body: the active tab. Panels, tiles, selection style, fonts and the animated background all follow the active theme.
  • Footer hints: the buttons that currently do something. They use your configured Confirm/Cancel mapping, so Circle and Cross swap if you changed Settings > Input > Confirm button.
  • Toasts and the activity indicator: short confirmations (for example Added to Favorites) and a small indicator above the hints while background work (folder listings, artwork, library scans, saves) is running. The cursor never waits for the memory card or a slow device.
  • Loading overlay: starting a device's drivers, launching an application and long file operations run behind a modal overlay with a status line and, for file operations, a progress bar.

The startup tab is configurable (Settings > Home & applications > Start screen: Home, Files, Tools or Settings; default Home). Older saved values for the retired Apps and Devices pages map to Home and Files; no favorites or metadata are rewritten.

Home

Home has two rows. Up/Down moves between them (an empty row is skipped), Left/Right moves within a row and wraps around, and L2/R2 jump to the first/last entry.

Continue row

Up to 24 tiles, in this order: pinned applications (including apps whose metadata says pinned = 1), then recent applications (as many as Recent applications allows: 0, 4, 8, 12 or 16; default 8), then favorites. If that leaves fewer than six tiles, the first applications of the library fill the row so a fresh install is not empty. Stored shortcuts whose device is not currently mounted are kept but hidden until the device returns. Pins and favorites show a small badge; recents do not.

Browse & shortcuts row

  • Applications opens the full library nested inside Home. Back returns to Home. This chip is always present.
  • Last folder appears once the browser has a valid remembered location and jumps to it in the Files tab. Always present when available.
  • Launch-key shortcuts are one chip for every launch key that has a target (Launch key Circle: ...). Disable them with Settings > Home & applications > Home quick-launch shortcuts; Applications and Last folder stay.

Background-only view

R3 on Home hides the interface so you can see the animated background; the footer keeps a single R3 Show interface hint. Press R3 again to restore. SELECT+R3 is still the R3 launch key. The hidden state is never saved across launches.

Applications library

Home > Applications shows the library as Grid (5 columns), List (9 rows plus a detail panel) or Carousel (depth carousel). SELECT cycles the view (saved), Triangle opens the library menu (application options, change view, filter, refresh) and Square toggles Favorite. The filter is one of All, Favorites (favorites and pinned), Memory Cards, MASS, HDD and Other devices, and is remembered. Full details, artwork rules and metadata are on the Applications page.

Files

Files is a persistent tab using the same engine as the modal browser opened from Tools. At the device root you select a device; devices that need a driver start when you open them (Not checked is not the same as absent). Back goes to the parent folder; at the device root it returns to Home. L1/R1 still switch tabs while you are inside a folder. The device root also carries a Built-in commands entry (the classic MISC folder). Everything about browsing, copy/move/delete, sorting and the image viewer is on the File Browser page.

USB directory reads are asynchronous. After a tab change, input stays guarded until any outstanding USB read has finished and the pad state has been re-armed, so a tab switch can never poll the controller during an active fileXio read.

Tools

Tools is a grouped list with a detail card for the focused entry (Up/Down, L2/R2 jump six rows, Confirm runs it). A small coloured dot marks entries with a safety note (amber, shown in the card) or entries that leave Launchstation or change console state (red; these always ask for confirmation first).

START menu

START opens the global Dashboard menu on every tab: Home, Refresh application library, File Browser, Settings, Reboot IOP (reset drivers) and Power off. Reboot IOP and Power off ask for confirmation. Switching tabs from this menu goes through the same unsaved-Settings guard as L1/R1.

Launch keys and quick launch

Every controller button can be assigned an application or built-in command under Settings > Launching > Launch keys (Circle, Cross, Square, Triangle, L1, R1, L2, R2, L3, R3, START, plus optional Left and Right). SELECT is reserved for the configuration shortcut. Two ways to use them:

  • Quick launch: hold SELECT anywhere in the dashboard; after a quarter of a second a Launch keys panel lists every assigned key. While SELECT is held, pressing a button starts its target instead of navigating. A short SELECT tap (under half a second, with no other button) keeps its normal meaning, such as cycling the application view. Pressing a button with no target shows a toast pointing to the setting.
  • At boot: a launch key held when the startup delay ends starts that target before the dashboard is used.

A fresh configuration assigns Circle to the File Browser and Triangle to About, which is why those two appear as Home shortcuts out of the box.

Boot behaviour

  1. Startup delay (Settings > Launching > Automatic start & boot, default 1 second, 0 to 60): input is ignored during the delay so a button used to start Launchstation is not misread. A launch key held when the delay ends starts its target.
  2. Automatic start: if the Automatic start target is set, a banner Starting NAME in N counts down (Automatic start timeout, default 10 seconds). Press any button to stay cancels it with the toast Automatic start cancelled. Clear the target to disable automatic start.
  3. Recovery boot: hold SELECT while Launchstation starts. For that session DASHBOARD.CNF is ignored (nothing saved is changed, a toast says so) and all device families are listed, so a bad saved device/auto-start combination can never trap you.
  4. Welcome message: the first time the dashboard fades in it shows a short introduction. Settings > System > Show welcome message again repeats it.

Devices and driver start-up

Only the device you booted from is always on. Other families (USB, internal HDD, exFAT HDD, MMCE, MX4SIO, UDPFS and, where built, iLink) start when you open them or when enabled under Settings > Storage & devices > Start devices automatically (all off by default). Optional storage is dimmed and marked Not checked until a root check succeeds; checks are user- or auto-start-initiated, never run while drawing, and are not continuous hotplug monitoring for optional families. See Device Support.

Rendering notes

The dashboard enables gsKit double buffering at start and flips at VBLANK to avoid horizontal tear bands from animated drawing. The second frame costs about 1.1 MiB (NTSC/480p) or 1.25 MiB (PAL) of the 4 MiB GS VRAM, so artwork is limited to small thumbnails (at most 128x128, up to 40 cached). This is a code-level anti-tearing measure; whether every console/display combination is free of flicker has to be confirmed on hardware. Animations run on a measured visual clock, so menu easing does not assume 60 frames per second, and a long blocking operation never makes an animation jump forward more than 100 ms. See Motion and Troubleshooting.
