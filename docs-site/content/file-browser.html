File Browser

Files is a first-class, persistent dashboard tab using the native browser. The separate modal browser is also available from Tools; classic wLaunchELF file operations remain supported through the shared backends.

Tab and folder continuity

Files opens directly into the browser without a separate landing page. L1/R1 switches top-level dashboard tabs; returning preserves the browser folder and selection. The Home tab provides the Last folder shortcut. MISC commands are grouped under Tools, not listed as independent top-level tabs.

Opening files

  • .PNG, .JPG, .JPEG — open in the native dashboard image viewer. PNG uses the existing bounded libpng decoder; JPEG uses a bounded libjpeg path derived from the historical wLaunchELF JPG support.
  • Image viewer controls: Left/Right browse other PNG/JPG/JPEG images in the current sorted folder (wrapping at either end), Up/Down rotate 90 degrees, L2/R2 zoom, left stick pans while zoomed, Square toggles fullscreen, Start toggles slideshow, L1/R1 changes the 1-60 second slideshow delay, Select resets the view, and Confirm/Back closes the viewer. Slideshow uses the same mixed-format folder order.
  • .ELF, .XLF, .KELF — executable launch path.
  • .VCD — POPStarter PS1 handoff.
  • .CUE, .BIN, PS1 .EXE — Ember when the image is directly inside <umbrella>/games/<Game>/. The umbrella name is not fixed.
  • .ISO — Neutrino PS2 handoff.
  • Text/config formats — dashboard Text Editor.
  • Folders — enter folder.

Ember handoff

USB Ember launches use a clean IOP handoff. Launchstation finishes background I/O and audio, resets the IOP, and rebuilds only the USB filesystem stack before starting Ember. The launcher deliberately does not reload its homebrew SIO2MAN/PADMAN modules; Ember loads the ROM pad modules itself. This avoids the hardware-observed pad init rc=-1 conflict while keeping the selected USB game tree mounted again before Ember starts.

Operations

Triangle opens contextual operations. Depending on device and file type, the browser can copy, cut, paste, rename, delete, create folders, calculate size, edit or organize timestamps, work with PSU saves, mount VMC images, edit text or invoke specialist tools.

Selection

Square marks entries. Operations apply to the marked set; otherwise they apply to the focused entry. Classic exploit-protection checks remain for sensitive memory-card paths.

Sorting

The dashboard browser supports As Stored, Name, Game Title, Size, Date-Time and Kind. Sorted modes can be Ascending or Descending. Folders remain grouped first even in descending order.

Classic File Browser: four display modes

The classic L1 mode menu now supports four upstream-compatible display modes: File names, File names + details, Game titles and Game titles + details. Circle switches between filename modes, while Square switches between title modes; each repeated press toggles the detail column. The game-title modes use existing title metadata and the Shift-JIS renderer, while the two no-details modes use the full row width. Filename/title sorting and ascending/descending controls remain independent.

The dashboard Files tab and its modal browser also provide filename/title modes with optional details. These display controls do not start a device scan or change storage initialization.

Classic file-browser improvements (October 2026)

The classic modal File Browser's L1 display/sort menu now supports reversible sorting: choose Filename (D-pad Down), Game title (Left) or Timestamp (Up); press the same direction again to reverse its order. Right selects No sort. Triangle returns to the browser. Folders remain ahead of files and ELF entries ahead of other files in both directions. The dashboard Files tab already has its own independent six-mode ascending/descending sort selector.

In memory-card save titles, Launchstation now respects icon.sys's title line-break offset for PS2 save folders and PSU archives, adding a separator without splitting Shift-JIS characters or duplicating existing spaces. The *Tuna Date operation for a selected real MC folder is now inside Folder dates..., with Manual, A-Z, Z-A and SAS ordering. It is deliberately absent when the selection is not an eligible physical memory-card folder; the older HDD/PFS date functions are unchanged.

Size and date-time

Size and date-time occupy independent columns with an explicit gutter. Seconds are retained. Filename width is calculated from actual metadata width so full timestamps fit rather than being shortened.

Root devices

Root entries show friendly names plus mount IDs. USB is named USB Mass Storage and displays mass:, mass0:, mass1: and so on, while internal routing retains device identity. Loading and errors are reported when opening a device; diagnostic status remains available in device tools. Unsupported consoles do not show or probe PS2 i.Link storage. USB discovery does not assume a permanent mass0:.

Rows and navigation

The native browser and path picker show ten rows within the dashboard safe area, with centered scrolling where the list permits it. Up/Down wraps one item at a time. Left/Right pages to an endpoint before wrapping on the next press; subsequent presses resume paging. The classic browser retains its display-dependent capacity and existing endpoint-first paging.

Copy and delete progress

File operations use a compact action/filename line, remaining size in MB for copying and verification, and a themed progress bar. Deletion shows completed selected items and the current filename, including files inside a selected folder; its bar measures selected items rather than recursive bytes. A completed transfer fills the bar before the popup closes. The background updates between returning filesystem calls; an individual blocking device call can still pause drawing.

Paste failures retain the numeric error and transfer stage alongside a plain-language reason. Insufficient space, access denied and read-only filesystems have distinct explanations. A replacement needs space for the new file while the existing file is preserved.
