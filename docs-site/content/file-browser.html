File Browser

Files is a first-class, persistent dashboard tab built on the native browser. The same engine also opens as a modal from Tools, launch keys and Application options (Show in File Browser). It copies, moves, renames and deletes, builds and extracts PSU saves, mounts memory card images, edits folder dates, opens images and text, and launches executables and game images through the shared loader.

The Files tab

  • Files opens straight into the browser inside the dashboard frame; there is no separate landing page. L1/R1 switch top-level tabs even from inside a folder. Returning to Files restores the folder and the highlighted entry.
  • Back goes to the parent folder (and re-selects the folder you came from). At the device root, Back returns to Home. In the modal browser Back at the root closes it.
  • Home > Last folder jumps to the most recent folder you opened. It is remembered for the session.
  • Folder reads, titles and free-space lookups run on a background worker, so the cursor stays responsive. A Reading folder... spinner shows while a listing is in flight. A folder lists at most 2048 entries.
  • The header lane shows the current path, the item count and, on devices that report it, the free space (MB/GB). With a selection it shows N of M selected. A clipboard note (Clipboard: N to copy/move) and a launch-argument note appear when relevant.

Device root

The root lists the device classes the build supports, each with a status line. Entries can be opened while they say Not checked; opening starts the demand-loaded driver stack and refreshes the state. A device that was explicitly checked and found absent is skipped by navigation. USB discovery never assumes a permanent mass0:; USB units are shown under the public MASS name even though their internal path may be usbN:.

Image viewer

PNG uses a bounded libpng path (files up to 1.5 MB, 2048x2048; interlaced PNGs only up to 256x256) and JPEG a bounded libjpeg path (up to 4 MB and 8192 pixels per side). Large images are downsampled to the screen when loaded, so the viewer never keeps a full-size image in memory. Files that are damaged, unsupported or over the limits show a message instead of opening.

Selection and the clipboard

Square marks entries (marked rows show a green check). Operations apply to the marked set; otherwise to the focused entry. The menu offers Select all, Invert selection and Clear selection. Copy and Cut fill the clipboard (the marks are cleared and a toast reads N items ready to paste/move); Paste here copies or, after Cut, moves. The clipboard is dropped if the IOP is reset, because device paths may no longer be valid. Classic exploit-protection checks still guard sensitive memory-card system folders (renaming, cutting, deleting and pasting there ask first or are refused).

Progress overlay

Paste, move and delete use a file-operation overlay: a title (Pasting file, Moving file, Deleting file), the current name on its own full-width row, Remaining size: N MB (copy) or Completed items N / M (delete), and a progress bar. The bar fills completely before the overlay closes. Classic prompts raised by older code (yes/no questions, names) appear as dashboard dialogs.

Show: four display modes

Choose Triangle > Show. The default is Names and details.

ModeRow content
File namesThe full row width for the name.
Names and detailsName, size and date-time. Size and date-time sit in independent columns with a gutter; seconds are shown and the name width is calculated from the real metadata width.
Game titles and detailsSave or PSU titles instead of names (falling back to the name), plus size and date-time.
Game titlesTitles only, full row width.

Titles come from PS2 icon.sys, PS1 saves and PSU archives, are decoded as Shift-JIS and respect the title line-break offset. Filenames always stay literal. The choice lasts for the session and is not written to a configuration file.

Sort by

Choose Triangle > Sort by, then a direction. Modes: Type (default: folders, executables, text files, then everything else grouped by extension), As stored (device order), Name (ascending), Game title, Size, Date-Time and Kind (extension). Ascending/Descending apply to every mode except As stored. Folders always stay first, even in descending order; descending reverses only the order inside the folder and file groups. Ties fall back to the name. The native browser does not move ELF files above other files. HDD partition lists always keep the drive's own order. Date-Time ascending is oldest first.

Bookmarks (PathPad)

Triangle > Bookmarks... lists up to 30 saved folders. Pick one to jump to it, Bookmark this folder, or Remove a bookmark.... If all 30 slots are used you choose which to replace. Bookmarks are stored in LAUNCHELF.CNF (PathPad[00] to PathPad[29]) and saving them writes that file immediately. Settings > Launching > Lock shortcuts & bookmarks disables editing.

File and folder pickers

Settings (paths, launch-key targets, application folders), the Text Editor (Open...), launch-with-arguments and several tools choose paths with a lighter picker that shows the same device list and reads folders on the background worker, so it never freezes on a slow device. Up/Down move (wrapping), L2/R2 jump to the first/last row, Confirm opens a folder or chooses a file, Back goes up one level (cancels at the device root) and Triangle cancels. In a folder picker the first row is Use this folder and START chooses the current folder directly. R3 chooses the highlighted file as a uLE:/ path relative to Launchstation's own folder (so it follows the program if it moves); elsewhere R3 jumps to that folder.

Ember handoff

USB Ember launches use a clean IOP handoff. Launchstation finishes background I/O and audio, resets the IOP and rebuilds only the USB filesystem stack before starting Ember. It deliberately does not reload its own pad modules because Ember loads the ROM pad modules itself, which avoids the hardware-observed pad init rc=-1 conflict. The selected USB game tree is mounted again before Ember starts.

Classic modal browser (legacy)

The original wLaunchELF browser code (L1 display/sort menu, R2 PathPad) still exists in the source for compatibility and for a few legacy dialogs. Every entry point in the dashboard (Tools, launch keys, MISC commands, Application options) now opens the native browser described above, so you should not normally encounter it. The older sort and display model it used is documented in docs/FileBrowser sort+display modes.txt for reference.
