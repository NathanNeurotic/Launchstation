FTP, PS2Link & Remote Control

The FTP server, the PS2Link host filesystem and the MrRexD-compatible PC command protocol are embedded in the standard and DualShock builds, but none of them starts at boot.

Read this before you start FTP
Launchstation starts the FTP server with anonymous logins enabled. Anyone on your network can log in as anonymous (any password) and read, write, rename or delete files on every storage device the console has mounted. The stock ps2dev/ps2dev account is also accepted. Use it only on a network you control, and stop it (reboot the IOP, or leave Launchstation) when you are done.

FTP

Open Tools > FTP / Remote access (the MISC command PS2Net). Launchstation first starts the ATA/exFAT drive so ata0: can hold the command inbox (FTP still starts if no such drive exists), then loads the ETH network stack, ps2netfs and ps2ftpd, reads IPCONFIG.DAT, and shows Net Config: ip netmask gateway. Connect from a PC to that address on port 21. The server implements the classic command set (PORT, PASV, LIST/NLST, RETR, STOR, APPE, REST, SIZE, DELE, MKD/RMD, RNFR/RNTO); it has no FEAT, EPSV or MLSD, so clients should be set to plain passive mode without them (the Cloud Relay script sets disable_epsv and disable_mlsd for rclone). Only storage devices that are already started appear in the FTP tree, so open a USB or other device in Launchstation first if you need it.

  • The server is the legacy ps2ftpd by Jesper Svennevid (AFL-2.0), unchanged apart from build integration. Its port, username and password are the compiled defaults; no Launchstation setting changes them.
  • FTP is not affected by Allow writing over the network; that setting only gates File Browser writes on host: and udpfs:.
  • FTP and UDPFS cannot be loaded at the same time. Opening udpfs: while FTP is running makes Launchstation reset the IOP (the PC game receiver does this and restores FTP afterwards).
  • FTP shares DEV9 with HDD/ATA, and runs through the same IOP as USB and memory cards. Avoid transfers while a backup, recovery or other storage-heavy job is active.

PS2Link host filesystem

Launchstation embeds ps2host, the file-I/O half of PS2Link. It loads the first time you open Network Host (host:) in Devices or the File Browser, and listens on TCP port 18193 (0x4711) for a PC running a PS2Link-compatible client such as PS2Client. The PC then serves its files as host:. If the PC provides elflist.txt, the root shows that list instead of a directory. The PS2Link remote-execute and debug-print features are not included. Writing to host: from the File Browser needs Allow writing over the network.

R3Z remote commands (PC to PS2)

The command protocol follows oMrRexD's Command PS2 helper rather than inventing a second desktop client. The PC uploads one small file over FTP; Launchstation polls for it every 3 seconds, but only while the dashboard is on Home, FTP is running, no file job is busy and no boot or IOP park is in progress.

ItemValue
Fileata0:/PS2-COMANDO.TXT (needs an ATA/HDD at ata0:)
LayoutLine 1 PS2-COMANDO 1, line 2 the command, then a line FIM. The file is ignored until FIM appears, so a half-uploaded file is never consumed. It is read at most 1 KB.
EXECUTAR<TAB>pathLaunch an application by path (for example mass:/APPS/FOO.ELF). Paths without a device (:) are rejected.
MENUOpen the configured OSDSYS path.
DESLIGARPower off the console.

The file is deleted as soon as it is complete, including malformed or unknown requests, which show an error toast. Treat this protocol as trusted-LAN remote control: anyone who can FTP in can launch programs or power the console off.

PC game receiver (PS2-RECEBER.TXT)

MrRexD's Send Games to PS2 tool uses a second job file, polled on the same terms:

ItemValue
Requestata0:/PS2-RECEBER.TXT: line 1 PS2-RECEBER 1, then up to 32 lines DVD|CD<TAB>size<TAB>filename, then FIM. Names may not contain slashes.
FlowSwitch FTP to UDPFS, wait up to about 10 seconds for the server, copy each file from udpfs:/<filename> to ata0:/PS2-RECEBENDO/ in 256 KB blocks (reserving the final size first), then rename into ata0:/DVD/ or ata0:/CD/. Existing files are skipped.
RecoveryA dropped transfer reloads the UDPFS and ATA drivers and resumes from the last byte, up to 8 times per file. A failed or cancelled file is removed from staging and stops the job. Triangle cancels after confirmation.
Resultata0:/PS2-RECEBER.RES (PS2-RECEBER-RES 1): one line per file with state OK, JA_EXISTIA, NAO_FEITO, FALHOU, CANCELADO, SEM_SERVIDOR or FICOU_EM_PS2-RECEBENDO, bytes written, seconds and name, ending with FIM. FTP is restored before the PC reads it.

Recommended troubleshooting sequence

  1. Confirm physical Ethernet/link and adapter initialization (see Failure isolation).
  2. Confirm IP, netmask and gateway on both ends.
  3. Start only the intended service and test it with a plain FTP client before using PC helper tools.
  4. For remote commands or transfers, confirm that ata0: is present, that Launchstation is on Home, and that the job file ended with FIM.
  5. Then debug the higher-level request.

Network exposure

These are homebrew console services, not hardened internet-facing daemons: FTP allows anonymous read/write access, the PS2Link host accepts any PC that connects, and the remote-command files are unauthenticated. Keep the PS2 on a trusted local network, do not forward its ports from a router, and do not run FTP on shared or public Wi-Fi/LAN segments.
