PS2 ISO Launching · Neutrino

Open a PS2 .ISO in the File Browser and Launchstation hands it to an external Neutrino installation, with Neutrino’s per-game compatibility and video options one dialog away.

External core

Neutrino is not embedded in Launchstation. Install a compatible Neutrino package separately; Launchstation resolves it, validates the image, builds the command line and keeps the storage stack alive for the hand-off. Neutrino itself decides what games run; Launchstation does not patch its disc drivers.

Quick start

  1. Put a Neutrino install on the game device (USB, MMCE, MX4SIO, iLink, exFAT HDD or UDPFS), or on a memory card: <device>/neutrino/neutrino.elf with its config/system.toml and module folders.
  2. Put the .ISO anywhere on one of those devices.
  3. In Files, select the ISO and press OK. Choose options (or just Run game).

Loader search order

  1. Explicit path – Settings > Launching > Disc & image loaders > Neutrino.
  2. The ISO’s own device – /NEUTRINO/neutrino.elf, /neutrino/neutrino.elf, /NEUTRINO/NEUTRINO.ELF and /neutrino/NEUTRINO.ELF at the device root.
  3. mc0: – the same four forms.
  4. mc1: – the same four forms.

Only a usable installation is a candidate (next section). If none qualifies you get “Neutrino not found (set its path in Settings)”.

Usable installation

A candidate needs a readable ELF (valid ELF header) and either modern config/system.toml or legacy system.toml beside the ELF. Launchstation does not require any particular module-folder generation. The working directory handed to Neutrino is the folder holding neutrino.elf, so a custom path must contain a folder separator.

Per-launch compatibility and video options

Selecting a valid ISO opens Neutrino launch options (a dashboard dialog, or the classic screen in the classic UI). Use the D-pad to select and change, then Run game or Cancel. Cancel exits before any Neutrino file is touched.

Optional per-game profiles

For an ISO with a valid SYSTEM.CNF Game ID such as SLUS_123.45, the dialog shows that ID, loads any saved profile first, and offers Save for this game and Reset this launch. Run game never saves by itself; Reset this launch clears the current choices without deleting the stored profile.

A profile is two checksum-verified files, NEUT-<GameID>-A.CNF and -B.CNF, in Launchstation’s own dashboard settings folder (not beside the ISO and not in LAUNCHELF.CNF). Each save writes the older or invalid slot, so the last valid copy survives an interrupted write; a malformed profile is ignored. Only verified Game IDs can be saved. If the settings location is unavailable, or is a memory card that cannot be touched while an MMCE/MX4SIO stack owns the bus, the profile is simply skipped and the launch proceeds. No ISO, VMC or game data is modified.

Settings > Launching > Disc & image loaders also has independent Disable Ember / POPStarter / Neutrino support switches (all Off by default); a disabled Neutrino refuses ISOs before reading them.

Launch arguments

-bsd=<backend>
-dvd=<device:path/to/game.iso>
-qb
-cwd=<neutrino install directory>
[-gc=…] [-gsm=…] [-dbc] [-logo]

-qb is Neutrino’s quick-boot. The numeric unit suffix of a path, where present, is accepted by Neutrino’s backend detection. Argument text is limited, and an over-long path is refused with “Neutrino launch arguments are too long”.

Image validation

Launchstation opens the image, reads sector 16 and requires an ISO9660 primary volume descriptor with the CD001 signature, otherwise it stops with “ISO9660 image could not be read”. This proves the file is an ISO9660 image, not that the game will run.

Game ID, RetroGem and MMCE cards

Launchstation reads a valid PS2 title ID such as SLUS_123.45 from the ISO’s root SYSTEM.CNF BOOT2 line (a bounded read; no drivers are loaded or reset for it). It is used three ways:

  • Profiles (above).
  • RetroGem display. With Game ID launch signal for discs on, the signal is drawn after cleanup, just before the hand-off. See RetroGem Game ID.
  • MMCE card switch (best effort). If an MMCE manager is already running, or can be started without touching other storage, Launchstation asks responding adapters to switch to that title’s card. It skips the slot holding the ISO and the slot holding Neutrino, never switches an ambiguous alias, and never replaces an active or resident MX4SIO stack for this step. A successful request may wait briefly (up to 15 status polls) for the card to report ready. A missing Game ID, an unresponsive card or an error never stops the launch. The RetroGem setting does not disable this step.

This conservative policy intentionally differs from upstream R3Z, which initialises MMCE unconditionally.

Keep-IOP hand-off

Neutrino consumes the already-mounted backing store. ISO launches therefore drain Launchstation’s background I/O, release the controller library and jump to Neutrino on a live IOP. They do not obey Reset IOP before launch, and Launchstation never resets the storage stack on the way out.

If a game does not boot

  1. Check the message: not found (no usable Neutrino), could not be prepared (the ELF cannot be read/loaded), not supported from this device (APA/mc/CF/disc source), ISO9660 image could not be read (damaged or non-ISO).
  2. Verify the same ISO can be read in the File Browser from that device.
  3. Set the Neutrino path explicitly to remove discovery ambiguity.
  4. Confirm the install has config/system.toml (or a legacy adjacent system.toml) and the module files for your Neutrino version.
  5. Try a known-good ISO on the same backend, then with all compatibility toggles Off.
  6. If the screen is wrong, retry with video mode Original and video compatibility Off.
  7. Report the exact Launchstation hash, Neutrino version, the device backend and the option set.
