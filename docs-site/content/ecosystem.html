SD2Cloud & ORBIT Comparison

What two related community PS2 projects do, how Launchstation compares today, and which gaps remain open.

Two community PS2 homebrew projects overlap with parts of Launchstation. This page records what each one does, how that compares to Launchstation today, and where the gaps are. It is a documentation and planning aid, not a claim of parity.

  • Upstream facts come from each project's public README as read on 2026-10-26. Both projects change quickly; recheck before relying on a row.
  • "Launchstation" entries come from this repository's own documentation. Where this page says not audited, nobody has compared that feature against the code or tested it on a console.
  • No source code from either project is incorporated. Both are GPL-3.0; this repository has no single root licence (see THIRD_PARTY_CREDITS.md), so copying their code would need a licence decision first. Launchstation's Google Drive client is original (NATIVE_CLOUD.md).

SD2Cloud

oMrRexD/sd2cloud by MrRexD, GPL-3.0. A PS2 application that manages and backs up memory cards on the console itself, to Google Drive, with no PC. Works with sd2psx-family cards running the sd2psXtd firmware (the PS2 sees them as MMCE), MemCard PRO2, regular memory cards, OPL virtual memory cards and card files on USB, MX4SIO or the internal HDD.

The authoritative checklist for closing these gaps is issue #108 ("GUI parity: complete on-console SD2Cloud/MMCE management workflows"). #226 (merged 2026-10-28) added card contents, safety copies, card resize, the active-card check and card switching, and the IGR fingerprint backup. None of it is tested on a console yet. Rows still marked Partial or Missing remain open. tests/test_sd2cloud_parity.py checks that labels and features are present; the #226 host tests (test_mc_card_write, test_dash_card_tool and others) exercise the card code under simulation, which still does not prove the workflows on hardware.

ORBIT

danielnuld/ps2-launcher, GPL-3.0 (its bundled Neutrino fork is AFL-3.0). A game launcher for a real PS2 that starts games through Neutrino. Companion app ORBIT Jellyfin is tracked in issue #186. ORBIT has no Google Drive feature; its "cloud" overlap is network-delivered content (covers, a home game server) and save icons.

Suggested order for closing gaps

The detailed, verified order is in the parity plan; in short:

  1. Finish auditing the remaining rows above against #108's acceptance criteria, recording implemented / partial / missing with evidence.
  2. Done in #226: the card image parser, the card contents view, the active-card check, card switching and the automatic safety copy before every card write. Next: hardware validation (the console test matrix in #226), then "All saves" and restore previews, which build on the same parser.
  3. Templates, the Library and per-save backup versions are later work that needs design decisions; they are not cheap first steps.
  4. Keep ORBIT-only ideas (RetroAchievements agent, in-game pause menu) as separate proposals; they need a Neutrino fork or an in-game agent and are a different risk class.
  5. Do not copy code from either project without settling the licence question above.
