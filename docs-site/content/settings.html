Settings Reference

Settings are grouped by purpose, apply as soon as you change them (themes, screen position and sound preview live) and are written only when you Save. One Save/Discard session covers the dashboard, Launchstation's classic settings and the network addresses.

How Settings works

  • Settings opens at the overview of eight groups plus Built-in commands (which opens the MISC list in the File Browser). Confirm or Right opens a group; Back returns to the previous page with its selection and scroll position intact; at the overview Back returns Home. A breadcrumb shows where a page lives and the top right shows no changes, unsaved changes, saving... or save failed.
  • Left/Right changes a choice or number; Confirm opens a list for choices with more than two values. Left goes back on rows that do not use it. L2/R2 jump to the first/last row. Square resets one theme row to its preset value, or edits a launch key's title.
  • Triangle opens the Changes menu on every page: Save changes, Discard changes, Keep editing. Leaving Settings (L1/R1, START menu, Back at the overview) with unsaved edits asks the same question.
  • Unavailable dependent options stay visible; pressing them shows what to enable first (for example Music volume needs Background music).
  • Edits compare the current serialized values with the snapshot taken when Settings opened, so returning a control to its original value leaves no false unsaved flag.

Theme-matched controller button icons

Control icon backings controls whether face-button and D-pad symbols and quick-action chips receive a theme-derived badge. When disabled, the symbols render without the backing. Symbols are generated from the built-in vector atlas and need no external icon PNGs.

Launch keys can target any application path or a built-in command (the MISC/... entries). A launch key held at boot, or SELECT + button in the dashboard, starts it; targets also appear as Home chips. See Dashboard.

Path pickers

Program and file settings use the native picker with Choose a location... and Clear location. POPStarter and Neutrino have explicit ELF path fields. Ember uses an Ember directory: the folder name and location are arbitrary, but the save-safe umbrella still contains ember.elf, bios.bin and games/<Game>/. When a selected game's own umbrella lacks ember.elf, the configured Ember directory can supply it to that device automatically. VCD remains POPStarter; CUE/BIN/EXE remains Ember. If the Neutrino path is empty, the game device and mc0:/mc1: neutrino/ folders are searched.

Colored Game ID launch bars

Game ID output for ELF/application launches is off by default on new configurations; it remains available in Settings > Launching > Game ID output for RetroGEM-compatible display adapters. Previously saved configurations keep their selected value until changed. The disc signal is on by default.

Unavailable devices

Show unavailable devices controls whether confirmed-missing devices are displayed. Hidden devices are removed from navigation as well as drawing. Unprobed (Not checked) devices remain actionable.

Start devices automatically

ON loads that family's drivers when the dashboard starts, so the device is ready and its applications are found by the startup scan. OFF never loads the driver by itself; the Files root can still start it manually, and drivers already loaded stay loaded until the next IOP reboot. The boot device is always on and cannot be switched off. MMCE and MX4SIO are alternate SIO2 storage stacks and cannot both auto-start: if a saved file enables both, the boot device wins, otherwise MMCE.

The Google account and update rows exist only in network builds with native cloud support. The IGR helper row compares installed helper bytes with the helper this build would install for the current application and backup paths. Entering this page is treated as an explicit request for live MMCE status: if a backup destination is set and MMCE is not already running, the MMCE stack is started on demand before the read-only status scan, even when MMCE auto-start is off. A startup failure is shown instead of leaving the page silently at Not checked. The pending check is read-only: it compares live card images with the newest local history without creating, pruning or deleting backups; PCSX2-format history is compared in memory.

Native update install

Check for updates validates ancestry against the rolling latest release. The updater selects the standard or DS34 PSU package for the running variant, verifies its advertised SHA-256 and contents over trusted HTTPS, stages the verified ELF and replaces the running app's ELF using a .BAK rollback file. The verified four-file PSU can restore missing updater CA and BGM sidecars but never overwrites existing customized sidecars. Interrupted .UPDATE/.PACKAGE staging files are preserved for manual recovery rather than silently truncated. Restart Launchstation to run the new build. Older update clients may need a one-time manual package install.

MMCE and Drive recovery

The MMCE backups page can select a local snapshot for non-destructive recovery. The Google account / Tools cloud menu can browse remote history and recover a SHA-256-qualified snapshot into a new image on USB/HDD. Neither flow automatically replaces a live MMCE card. Recovery details.

PS2 clock without a working CMOS battery

Use Settings > System > Set PS2 clock manually... and enter YYYY-MM-DD HH:MM:SS. Launchstation validates the date, writes the PS2 RTC and verifies the readback. With a dead clock battery the time may need setting again after power loss. Alternatively use the software clock, which keeps its own time until the next power-off, or Sync PS2 clock from Internet on network builds.

Languages

The nine built-in languages translate dashboard navigation, Settings labels, common actions and file-operation progress. An external .LNG overrides individual strings; missing strings fall back to the selected built-in language. Some extended help and specialist dialogs remain English; filenames, application titles, bookmarks, paths and protocol identifiers keep their original text.

Unsaved state

Settings compare current serialized values with the session snapshot. Touching a control and returning it to the original value does not leave a false dirty flag. Save failures remain visible and can be retried; Discard does not claim a failed write succeeded.

Reset actions

Display/theme reset actions restore known project defaults so you do not have to reverse each visual setting by hand: Reset screen settings, Reset appearance, the per-group Reset rows and the theme file resets.

Where things live

Home includes the Applications library and Last folder shortcut. Files runs the native File Browser directly. Tools holds the classic MISC commands in a popup menu (also reachable from Settings > Built-in commands and from the Files root). Separate Apps and Devices pages no longer exist as tabs; the old internal identifiers are kept only for compatibility.
