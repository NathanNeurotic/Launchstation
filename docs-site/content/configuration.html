Configuration Files & Paths

Classic CNF compatibility is retained while the dashboard, themes and cloud features add their own files. Everything is plain text you can edit on a PC; unknown keys are ignored and missing keys fall back to defaults, so old and new builds can share files.

Where files are found and saved

LAUNCHELF.CNF

  1. At startup LAUNCHELF.CNF is loaded from the folder the ELF was started from.
  2. If it is not there, mc0:/SYS-CONF/LAUNCHELF.CNF (or mc1:, preferring the slot Launchstation started from) is used.
  3. Configuration folder (CNF_Path, Settings > System) redirects loading and saving to another folder after the IOP reset; this is how HDD or disc installs find a CNF beside the ELF.
  4. Files larger than 128 KB are rejected. A file without CNF_version is treated as a legacy config.

A normal Save writes the file back to where it came from when it can; otherwise it falls back to a memory card SYS-CONF folder or the ELF's folder. Settings > System > Save launch & tool settings to... lets you choose explicitly between the configured folder, the folder next to the ELF and the memory card SYS-CONF, and writes immediately. The path used to load the configuration is tracked so the UI can explain where state came from. A recovery boot (hold SELECT) still loads LAUNCHELF.CNF but ignores DASHBOARD.CNF.

DASHBOARD.CNF, DASHAPPS.CNF, DASHLIB.CNF

The dashboard looks for DASHBOARD.CNF in, in order: the folder LAUNCHELF.CNF was loaded from (if on a writable device), the ELF's folder, then mc0:/SYS-CONF/. The first folder that has the file becomes the “dashboard folder” used for all dashboard files, THEMES/ and ART/. Writable devices are memory cards, USB, HDD, MMCE, MX4SIO, iLink and ATA. Nothing is written from the UI thread: a save marks the file dirty and a background job writes it once the controller has been idle for a moment, so a burst of changes becomes one memory card write. Writes are verified by reading the file back.

IPCONFIG.DAT

Loaded from the ELF's folder, otherwise from mc?:/SYS-CONF/. Defaults when none exists: IP 192.168.0.10, netmask 255.255.255.0, gateway 192.168.0.1.

Device path behavior

Launchstation has user-facing paths such as mass:, usb:, hdd0:/partition/ and mc:/ and resolves them into the concrete driver/mount needed for I/O. mc:/ tries both slots; uLE:/ paths (chosen with R3 in a picker) are relative to Launchstation's own folder. External-core launch code must distinguish the internal I/O path from the public path syntax the external core expects.

Cloud files are separate

OAuth client configuration, trust roots and refresh tokens are deliberately kept out of LAUNCHELF.CNF. See Cloud sidecars.
