Launch Arguments

Launchstation can pass your own command-line arguments to an ELF. They come from a sidecar .arg file, from a text file you load in the browser, from application metadata, or from a Text Editor buffer. Arguments apply to ordinary .ELF, .KELF and .XLF launches.

Where arguments come from

File Browser workflow

  1. Highlight a Text Editor-supported file that contains your arguments (for example .arg or .txt).
  2. Press Triangle and choose Use as launch arguments (shown with “then choose the application”).
  3. Launchstation parses the lines and caches them in memory. A note N launch arguments loaded: choose the application appears above the list.
  4. Select the target ELF. The cached arguments follow the normal handoff path.

Use Triangle > Clear launch arguments to drop them. They are also dropped when you leave the browser, when you start anything that is not an ELF/KELF/XLF, and after any failed launch.

For one-off use on a single ELF, Start with arguments... in the same menu opens that ELF's sidecar .arg in the editor for you.

Text Editor workflow

The Text Editor offers the same action for the current in-memory buffer. After Launch with these arguments... succeeds the editor closes and the dashboard asks Start which application with these arguments? with a file picker. The editor validates first and shows Arguments not usable if the buffer is empty or exceeds a limit. It is convenient for testing flags without repeatedly writing the file.

Automatic sidecar arguments

For an ordinary ELF launch, Launchstation checks for a same-directory sidecar whose base name matches the ELF (the extension is replaced by .arg):

APPS/
├── BOOT.ELF
└── BOOT.arg

If arguments were already loaded manually (browser or editor), the sidecar is ignored for that launch. For memory card paths such as mc:/... the sidecar is looked up on the card the ELF was actually found on.

Precedence

  1. Arguments already loaded in memory (browser, Text Editor, Start with arguments...).
  2. The sidecar .arg file beside the ELF.
  3. Metadata arg lines, only when no sidecar exists.

Format and limits

RuleCurrent limit
One non-empty lineOne user argument
User arguments12 lines
Characters per argument255
Total cached argument text2,048 bytes including terminators

Line endings (CR, LF or CR/LF) are stripped and empty lines are skipped. Other characters on each line, including spaces, are preserved, so one line is one argument, not a shell command line. A NUL byte makes the file invalid. If a limit is exceeded, nothing is loaded and a message names the limit; a file with no usable lines reports that it is empty.

argv

The target executable still receives the normal selected/handoff path as argv[0]; your lines follow it as argv[1] onward.

Game images and external cores

Image launches do not consume a stray argument cache: .VCD (POPStarter), .CUE/.BIN/.EXE (Ember), .ISO (Neutrino) and MISC commands clear it and build their own controlled argument set. Pending user arguments are not forwarded to them.
