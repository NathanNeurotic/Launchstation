# Native Google Drive backup

Launchstation contains an original Google Drive client for uploading the
versioned MMCE backup history directly from a PlayStation 2. It does not use
SD2Cloud source code.

## Design

The implementation uses Google's documented OAuth 2.0 device authorization
flow and Drive API v3. HTTPS is implemented in `src/cloud_http.c` using Mbed
TLS, which is built from upstream source by `scripts/build_cloud_tls.sh`.
The cloud code is part of this repository and follows this repository's
license. Mbed TLS remains under its upstream Apache-2.0 license.

Cloud networking is opt-in and demand-loaded. Normal Launchstation startup does
not start Ethernet or TLS merely because cloud support exists.

Native HTTPS sockets are nonblocking and use a 15-second no-progress timeout
for TCP connect, TLS handshake, reads and writes. DNS lookup itself is the
synchronous PS2IP resolver call and is not covered by that socket timeout; DNS
failure behavior therefore remains part of the real-hardware validation matrix.

## Files

Place these beside `DASHBOARD.CNF`:

- `WLE-CLOUD.CNF` — OAuth client ID and optional client secret.
- `WLE-CLOUD-CA.PEM` — trusted CA roots used to verify Google TLS.
- `WLE-CLOUD.TOK` — generated by Launchstation after account linking. This
  contains the user's refresh token and must not be shared.
- `WLE-CLOUD.TOK.NEW` — temporary verified recovery copy used only while
  replacing the refresh token. A completion marker is written last, so a
  partially written staging file is ignored and the intact primary token is
  retained. Disconnect removes both token files.

The standard and DualShock app ZIP/PSU packages include
`WLE-UPDATE-CA.PEM` for GitHub update checks, but do **not** contain the
user's Google OAuth client ID or the separate Google trust file
`WLE-CLOUD-CA.PEM`. Google Drive requires explicit setup; users can install
a Google CA PEM through the in-app Google Drive setup menu. The source
repository provides `res/WLE-CLOUD.CNF.example` as a configuration template.

## Google setup

1. Create or select a Google Cloud project.
2. Enable the Google Drive API.
3. Configure the OAuth consent screen as appropriate for the project.
4. Create an OAuth client for **TVs and Limited Input devices**.
5. Copy the client ID into `WLE-CLOUD.CNF`.
6. Copy `WLE-CLOUD.CNF` and `WLE-CLOUD-CA.PEM` beside `DASHBOARD.CNF`.
7. In Launchstation open Tools > Google Drive backup and choose Connect.
8. Visit the displayed Google verification URL on another device and enter
   the displayed code.

The requested scope is `https://www.googleapis.com/auth/drive.file`, not
whole-Drive access.

## Backup controls

Open Settings > Storage & devices > MMCE backups. **Backup folder** selects
the parent folder containing `WLE-MMCE-Backups`; it does not move existing
history. Save the setting before leaving Settings. If an OPL IGR helper is
already installed, reinstall it after changing the folder because the helper
embeds its destination.

The Google account menu offers two distinct actions:

- **Back up cards & upload** creates verified backups of changed MMCE cards,
  then uploads the local history to the linked Google Drive account. If no
  backup folder is saved, it asks for one. Both MMCE units are checked.
- **Upload existing backups** uploads history from the selected backup folder
  without reading live MMCE cards. It requires a linked account and a saved
  backup folder; installing the IGR helper is not required.

The Google account menu also has **Backup folder...**, so a missing destination
can be configured without leaving the menu. This action saves the selected
folder immediately, like the destination picker used by Sync all cards. Cancel
or selecting the current folder leaves settings unchanged. Changing an existing
folder asks for confirmation and reminds you to reinstall the IGR helper.
The card status **Locally backed up** describes only verified local backup
history; it does not claim that Google Drive has been checked.

Google Drive setup starts on the missing required item: client ID first, then
CA bundle. The optional client secret can remain empty. Returning from an
action preserves menu selection. Accepting an unchanged credential does not
disconnect the account or rewrite the configuration.

## Backup behavior

Cloud sync uploads the existing versioned `WLE-MMCE-Backups` tree. Before an
`.mcd` or `.ps2` file is uploaded, Launchstation validates its PS2 memory-card
header/geometry and exact expected file size; interrupted or truncated
final-named backups are rejected. Sync is copy-only: cloud files are never automatically deleted. Each uploaded
backup carries a private `wle_sha256` Drive `appProperties` value. A backup
is skipped only when the same folder already contains an item with both the
same filename and SHA-256; a same-name file with different content is preserved
as a separate Drive item. Legacy uploads without this property may therefore be
uploaded once more, after which subsequent syncs are content-aware. Automatic syncing after IGR is disabled by default and
can be enabled under Settings > Storage & devices > MMCE backups after Google
Drive is linked.

## Security

TLS certificate verification uses the PS2 system clock. Make sure the PS2 system date and time are reasonably correct; an invalid clock can make otherwise valid Google certificates appear expired or not yet valid.

TLS certificate verification is mandatory. PS2SDK's current `getrandom()`
path is not treated as sufficient by itself: Launchstation conditions its output
together with full-width COP0 Count samples, the PS2 RTC, action/runtime timing,
a local counter, and DNS/TCP timing through SHA-256 before Mbed TLS seeds its
CTR-DRBG. The PS2 has no documented general-purpose hardware TRNG, so this is a
defense-in-depth improvement rather than a claim of independently certified
hardware entropy. Resumable upload session URLs are
also restricted to Google's documented `https://www.googleapis.com/` origin
before the OAuth bearer token is sent. The upload path hashes an already-open
backup and streams that same file handle to TLS, avoiding a filename re-open
between content identity and upload. The refresh token is stored only on the
user's configured Launchstation settings device in `WLE-CLOUD.TOK` (with
`WLE-CLOUD.TOK.NEW` used only as a recoverable staging copy). Disconnect
removes both local token copies. Never publish either token file.
