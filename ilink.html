iLink / FireWire

IEEE 1394 (i.Link, FireWire) mass storage is an independent BDM transport. It appears as the iLink / FireWire device and behaves like the other FAT/exFAT block devices for browsing, file operations and Neutrino ISOs.

Only on consoles that have the port

The i.Link connector was removed from the SCPH-50000 series. Launchstation hides the card on retail consoles whose ROM is 1.70 or newer, without loading any driver to find out. The PSX (DESR) is treated as having the port. Consoles with an unknown or non-retail ROM keep the card visible. Hold SELECT at boot does not override this rule.

Opening iLink

The card starts Not checked (dim, “Not connected”). Selecting it loads, in order, the BDM core, the BDM/FatFs filesystem driver, iLinkman and IEEE1394_bd, then retries opening ilink:/ for up to three seconds while the bridge enumerates. When a filesystem answers, the card reads IEEE1394 storage ready; otherwise it becomes No iLink storage found. The dashboard refreshes after the probe. Optionally turn on Settings > Storage & devices > Start devices automatically > Auto-start iLink / FireWire; leave it off unless the console has a physical i.Link port.

iLink is not part of the MMCE/MX4SIO SIO2 choice: it can run beside USB, ATA and HDD and does not trigger an IOP reset.

File Browser

Once ready, ilink:/ lists, copies, renames and deletes like USB and exFAT HDD. Because the BDM namespace is shared, an i.Link unit can also be assigned a massN: name; the card and the browser handle either spelling. Test ordinary directory listing first when diagnosing a game-launch problem. The supported filesystems are FAT32 and exFAT.

Neutrino ISO source

Neutrino has an ilink backing-store driver. Selecting a .ISO hands Neutrino -bsd=ilink and the live iLink device stack, preserved so its quick-boot can use the existing mount. The image is validated (ISO9660 CD001 at sector 16) first. Neutrino itself must be installed on iLink, on a memory card (mc0:/mc1:) or at a path you set. See Neutrino. POPStarter VCDs are not supported from iLink; Ember folders are handed off with the mounted stack retained.

OPL IGR

If Launchstation itself is started from iLink, the WLE-IGR helper cannot live on the iLink disk: Tools > OPL IGR automatic MMCE backup installs a trampoline on a physical memory card (mc0:/BOOT/WLE-IGR.ELF or mc1:) that reloads the iLink drivers and relaunches Launchstation. See IGR.

Hardware notes

Bridge chipsets, enclosure firmware, disk formatting and cable quality all matter, and not every IEEE1394-to-SATA/IDE bridge is supported. A useful report includes the console model, bridge/enclosure, disk size and filesystem, whether the File Browser works, the exact Launchstation build hash and the Neutrino version.

Troubleshooting

  1. No iLink card. Your console is ROM 1.70 or newer (no port) or the build lacks iLink. Check Tools > Build information.
  2. “No iLink storage found”. Power the enclosure before the console, reseat the cable, then reopen the card. The probe waits three seconds; a bridge that takes longer to spin up may need Detect now afterward.
  3. Stalls while loading. Module entry and the first directory call are synchronous IOP calls; the loading screen cannot animate during a call that blocks. Report the bridge model and exact build.
  4. Unit number changed. massN: numbering follows attach order among USB, MX4SIO and iLink; use the device card rather than a remembered number.
