Each app folder contains its packed executable, title.cfg, WLE-UPDATE-CA.PEM for verified HTTPS updates, and BGM.ADP for background music. ZIP and PSU payloads match. Back up any existing settings before replacing an app folder.

DualShock build

The -DS packages enable the inherited PS3/PS4 USB/Bluetooth controller drivers. The standard packages use the standard PS2 pad driver. Build checks do not establish controller and storage coexistence on a real console.

Integrity and native updates

The native updater first verifies that the published release descends from the running Git commit (and refuses older, divergent or unverifiable updates). It then selects the PSU matching its controller variant, verifies GitHub's SHA-256 asset digest, extracts only the matching ELF, and validates its PS2 ELF header before staged replacement with rollback. Older updater builds expecting standalone ELFs or two-file PSUs require one manual installation of the new package before the four-file PSU can be used by the native updater. Subsequent native updates restore missing updater CA/BGM sidecars from the verified four-file PSU and replace the ELF; existing/custom sidecars are never overwritten. Updates from legacy two-file PSUs remain ELF-only. For bug reports, record the commit and package or ELF SHA-256.

The app packages include music and the update CA; standalone ELF installations can copy res/music.sad as BGM.ADP and res/WLE-UPDATE-CA.PEM alongside the ELF. Google Drive account configuration and its separate CA setup remain optional and are not bundled. Offline documentation can be generated with python docs-site/build.py --out build/docs --zip build/Launchstation-Documentation.zip.

Rolling publication policy

The rolling latest tag is refreshed by successful verified master CI publication, including docs-only commits. The four ZIP/PSU variants come from the same source commit and have recorded checksums. If a new build behaves differently on a particular PS2, use the known-good preserved baseline release and report console model, source hash, device and reproduction steps. CI and package integrity do not substitute for real hardware acceptance. See preserved USB-tested baseline.
