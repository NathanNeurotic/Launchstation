Launching Games & Images

Launchstation does not contain a game engine. It recognises the file you open, prepares the right external core or console service, and hands over control. This page ties the pieces together; each core has its own page for the details.

The Tools tab also has shortcuts (PS1 VCDs, PS1 images, PS2 ISOs) that simply open the File Browser at the device list with a reminder of where each core is configured. A .BIN or .EXE outside the Ember layout is not launched as a game.

Reset or keep the IOP?

LaunchIOP handling
Generic ELFFollows Settings > Launching > Reset IOP before launch (default on, recommended: the program gets a clean IOP). Hold the confirm button while the application starts to do the opposite for that one launch (skip the IOP reset when the setting is on); a quick tap behaves as before. The application options menu reminds you next to Start.
POPStarterFollows the same setting.
NeutrinoAlways keep-IOP: the mounted storage stack is handed to Neutrino.
EmberAlways keep-IOP after a controlled USB rebuild, if the game is on USB.
DiscConsole services (PS1DRV, boot ELF, DVD player) after normal cleanup.

Turning cores off

Settings > Launching > Disc & image loaders has Disable Ember support, Disable POPStarter support and Disable Neutrino support (all Off by default). A disabled core refuses its own file type with a message before reading the image, loading drivers or tearing anything down, and does not hand the file to another handler. This page of settings also holds the loader paths (ESR, OSDSYS, POPStarter, Ember directory, Neutrino).

Game ID signals

Before a hand-off Launchstation may draw a short RetroGem signal (discs on by default, apps off by default). Neutrino can additionally ask an MMCE adapter to switch to the game’s card. These are separate channels; see RetroGem Game ID and Neutrino Game ID.

When a launch fails

Failures are reported on the dashboard with a specific message (for example “POPStarter does not support that VCD path”, “Ember needs a user-supplied 512 KB bios.bin…”, “Neutrino not found”). Work down this list:

  1. Can the File Browser read the file from that device? If not, fix the device first (Device Support).
  2. Is the layout exactly what the core page describes (folder names, bios.bin, system.toml)?
  3. Set the core’s path explicitly in Settings to remove discovery ambiguity.
  4. Try the same image from a different device or after a clean boot with only that device started.
  5. Check it runs from the core’s own launcher; Launchstation cannot fix a game the external core rejects.
  6. Report the exact build hash, console model, device, filesystem and core version.
