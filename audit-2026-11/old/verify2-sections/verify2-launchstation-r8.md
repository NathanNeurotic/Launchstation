## 2. Reasoning for every non-VERIFIED verdict

### LAUNCHSTATION-212 — VERIFIED-DRIFT
The contradiction holds on both halves: the template's backend list at `docs/LAUNCHELF.CNF:370-371` omits SMB, and its "-qb" sentence at `:372` is unconditional, while SMB is a supported backend and suppresses `-qb`. The finding's code citations are off, however. Corrected code citations: SMB support is `src/neutrino_iso.c:132-133` (`if (smbPathKind(path) == SMB_PATH_V1 || smbPathKind(path) == SMB_PATH_V2) return "smb";` inside `neutrinoBsdForPath()`), not `:141-144` (that is `smbCoreLocal()`, which merely consumes the result); and the `-qb` suppression is `src/neutrino_iso.c:253` (`!strcmp(bsd,"smb") ? "" : "-qb\n"` in the launch-args `snprintf`), not `:259` (a comment about R3Z Neutrino options). Doc citations `:370-372` are exact.

### LAUNCHSTATION-213 — WEAKENED
Narrower truth: only the SMB2.CNF half is a contradiction. `CHANGELOG.md:52` does say "**Save share** writes the block into SMB2.CNF for you" and calls the raw editor "Edit SMB2.CNF as text", and that is false at the pin — `src/dash_settings.c:563-564` ("SMB2.CNF itself is never written"), `src/dash_settings.c:896` (shares "Saved in LAUNCHSTATION.CNF; an old SMB2.CNF is read until the first save"), and the changelog's own newer bullet at `CHANGELOG.md:26`. The title's second half — that "SMB1 opens via `smb1:/`" is wrong because "SMB1 is a folder in `smb:/`" — is not a contradiction: both are true at different layers, and the code itself uses the `smb1:/` phrasing. The share template in `src/dash_settings.c:3430-3434` says "SMB1 opens via smb1:/ without a label" and "1 = an SMB1-only server (opens via smb1:/)", and `src/dash_browser.c:301` reconciles the two: "the SMB1 share is a folder of the one SMB device; fullPath opens smb1:/". So the finding survives only as a one-clause (phantom SMB2.CNF write) finding, not two.

### LAUNCHSTATION-214 — REFUTED
The finding rests on an identifier search, not a mechanism search: it reports "no Deckard/75K gate exists anywhere" from an exhaustive grep for those strings, and lists the actual gates as PSX-only plus the Hide-HDD setting. The mechanism it missed is the Deckard gate itself, implemented as a ROM-version proxy. Defeating code: `src/main_startup.c:746-756` — `shouldHideHddAtaDevices()` returns `hide_hdd_ata_devices = (romver_prefix >= 220)` (also set at `src/main_startup.c:292`), and `src/filer.c:24-25` turns that into `HIDE_HDD_HDD01_ATA01` in `getHideHddMode()`, whose masks at `src/filer.c:30-31` hide both HDD and both ATA units; `src/dash_devices.c:401,405` gate the device cards on `filerShowHddUnit(0)` / `filerShowAtaUnit(0)`. The repo's own docs define the term exactly this way: `docs-site/content/special-hardware.html:8` ("Slim 'Deckard' class (ROM 2.20 or newer)" → HDD/ATA "Hidden automatically") and `:15`, corroborated by `docs-site/content/devices.html:45` and `docs-site/content/hdd.html:4`. Within the repo's own definition, `README.md:181`'s "Hidden on Deckard (SCPH-75K+) and PSX" is substantively correct; the only caveat is the SELECT-held override (`src/filer.c:21-22`, `boot_show_all_devices` → `HIDE_HDD_SHOW_ALL`), which `special-hardware.html:12` also documents. The PSX and Hide-HDD gates the finding cites are additional gates, not the only ones.

### LAUNCHSTATION-218 — WEAKENED
Narrower truth: four sites, not five, deny a root LICENSE exists. The explicit denials were re-read verbatim and are all false against the tracked root `LICENSE` (scoped 0BSD, 1,096 bytes, commit `05bc1b0`, 2026-11-02): `docs-site/content/credits.html:62` ("There is no repository-root LICENSE file at this audit snapshot"), `docs-site/content/contributing.html:6` ("There is no root `LICENSE` file"), `docs/THIRD_PARTY_CREDITS.md:73` ("There is **no root `LICENSE` file in this repository snapshot**"), and `docs/architecture-maintenance.md:132` ("There is no root `LICENSE`;"). The fifth cited site, `docs-site/content/ecosystem.html:4`, does not say that: it says "this repository has no single root licence" — a claim about a single licence covering the whole tree, which remains true at the pin precisely because the root LICENSE's own Scope section limits it to original Launchstation code. That site should be struck from the finding; the remaining four-site finding stands, as does the finding's own caveat that the "no blanket licence" caution stays valid.

Corrected description: `docs/architecture-maintenance.md:89-92` presents five files as "The largest hand-written sources today" (`dash_settings.c`, `dash_browser.c`, `init.c`, `main_exploit_installer.c`, `filer_browser.c`); measured at the pin the hand-written ranking is `dash_settings.c` 4096, `dash_browser.c` 3616, `init.c` 3205, `dash_card_tool.c` 2903, `filer.c` 2556, `filer_browser.c` 2528, `main_exploit_installer.c` 2519 — so the list omits the **4th- and 5th-largest** hand-written files while including the 6th and 7th; it does not omit "the two largest files" (the two largest hand-written files are listed, and the still-larger generated font files are explicitly excluded by the doc itself).
