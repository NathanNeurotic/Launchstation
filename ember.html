PS1 Image Launching · Ember

Ember is the second PS1 core beside POPStarter. The two do not compete for a preference: .VCD uses POPStarter, while a .CUE, .BIN or PS1 .EXE inside Ember’s folder layout uses Ember automatically.

External core and BIOS

Ember is not embedded in Launchstation, and neither Ember nor a PlayStation BIOS is supplied. Each game’s own umbrella folder needs your bios.bin (exactly 512 KB). If the umbrella lacks ember.elf, Launchstation can copy the one from your configured Ember directory into it once before launch (Settings > Launching > Disc & image loaders > Ember directory). The BIOS is never copied for you.

Save-safe layout

The umbrella folder can be named anything and live anywhere on a supported device. Launchstation finds it by looking for the first path component named games (any case): everything before it is the umbrella.

DEVICE:/
└── MY-EMBER/
    ├── ember.elf
    ├── bios.bin
    └── games/
        ├── Spyro 2 (Ripto's Rage)/
        │   ├── game.cue
        │   ├── track01.bin
        │   ├── MC1.vmc          created/used by Ember
        │   └── MC2.vmc          created/used by Ember
        └── Another Game/
            └── game.bin

Select a .CUE, .BIN or PS1 .EXE directly inside the game folder (not in a subfolder). Launchstation derives the bare folder name and passes that to Ember. Do not place another folder called games earlier in the path.

Why loose CUE files are refused

Ember can resolve looser layouts, but its memory-card path is always composed as games/<argument>/MC1.vmc and MC2.vmc. A loose games/Game.cue can boot while silently making the save path impossible. The browser therefore offers only the folder layout that can both launch and save correctly, and other .BIN/.EXE files are not hijacked by Ember: a launch is attempted only when the path matches this layout.

Which devices work

The path check does not name devices, so Ember images on any mounted device can be handed over. Dedicated handling exists for USB (reset and remount, below) and the internal APA HDD (the partition is mounted writable with write-through so saves are written immediately). Other stacks (MMCE, MX4SIO, iLink, exFAT HDD, UDPFS) keep their existing mount for the hand-off; those combinations have not been hardware-verified. PC CARD CF is blocked for all launches, and memory cards are too small for disc images.

Launch contract

Ember derives its working directory from target argv[0], so Launchstation preserves the real live path to ember.elf as argv[0]. The bare game-folder name is the only game argument. Names containing a path separator or a colon, beginning with .., or longer than 180 characters are refused (“Ember images must be directly inside <Ember directory>/games/<Game>/”).

USB reset and final keep-IOP hand-off

Ember requires a working game-device stack when control reaches it. For USB/MASS, Launchstation first finishes background I/O and audio, prepares a clean IOP without its own PADMAN, rediscovers the USB game and ember.elf even if the drive’s logical unit number changed, then executes Ember with no further IOP reset. A mismatched or ambiguous remount is refused (the console returns to the system menu rather than launching another drive). For non-USB paths the existing mounted stack is retained. This hand-off ignores the generic Reset IOP before launch preference.

Disable Ember support (default Off) refuses Ember launches before any image, BIOS or driver is touched; POPStarter and Neutrino are disabled independently.

RetroGem Game ID

With Game ID launch signal for discs on, a CUE/BIN launch derives the disc’s ID the same way a VCD does (the data track’s SYSTEM.CNF serial, then the shared PS1 timestamp database, then the file-name fallback) and draws the RetroGem signal after cleanup and, on USB, after the successful remount. A standalone .EXE without a matching same-name CUE gets no ID. Lookup is read-only. No MMCE card switch is sent. Details: Ember RetroGem Game ID.

Troubleshooting

  1. Confirm the selected image is directly under <umbrella>/games/<Game>/.
  2. “Ember needs a user-supplied 512 KB bios.bin in this game’s umbrella”: add the BIOS (exactly 524,288 bytes) next to ember.elf.
  3. “ember.elf is missing; set an Ember directory in Settings”: either copy ember.elf into the umbrella or point Ember directory at a folder containing it. If the umbrella already contains a broken ember.elf, Launchstation refuses instead of replacing it.
  4. “Could not stage configured ember.elf”: the umbrella device is read-only or full.
  5. USB hand-off messages: unplug extra drives and retry; if two USB drives are attached, report both.
  6. Save files not appearing: check that MC1.vmc / MC2.vmc are created inside the game’s folder and that the device is writable.
