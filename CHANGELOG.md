# Launchstation changelog

The `## Rolling` section below is the maintained summary shown on the GitHub [`latest`](https://github.com/NathanNeurotic/Launchstation/releases/tag/latest) release page (`scripts/release_notes.py` reads only its `- ` bullets, newest first, and stops at about 12 KB with a link to this file so the release stays small enough for the in-app update check). Dated sections after it are a condensed history grouped by theme, newest first; PR numbers refer to <https://github.com/NathanNeurotic/Launchstation/pulls>. CI success is not console acceptance: items marked pending hardware validation still need testing on a real PS2.

## Rolling

- **microSD icon and clearer MX4SIO name:** MMCE Slot 1/2 and the MX4SIO card now show a microSD card icon instead of the full-size SD card (PC CARD CF keeps the SD icon), and the MX4SIO device reads **MX4SIO SD Card Slot 2**. The FTP and SMB server tools show the shared-folder icon that network devices already use. From [R3Z3N (saildot4k)](https://github.com/saildot4k)'s fork. The icon atlas grows by one 32-pixel row for the new icon (16 KB). NOT TESTED on PCSX2 or a real PS2.
- **Skip one save when extracting several PSUs:** when several `.psu` files are extracted (Extract PSU, or straight onto a card from the File Browser) and one save is already on the card, answering **No** to "overwrite it?" now asks "Skip this save and extract the rest?". **Yes** keeps that save and its `.psu` (a Move leaves the `.psu` cut) and extracts the others; **No** stops, as before. The result names how many were skipped. A single `.psu` still asks once. From [R3Z3N (saildot4k)](https://github.com/saildot4k)'s fork. Host test `tests/test_copy_psu_listing.py`. NOT TESTED on PCSX2 or a real PS2.
- **PS2 system browser keeps FMCB's menu when FMCB allows it ([#346](https://github.com/NathanNeurotic/Launchstation/issues/346)), and a new OSDSYS (skip card update) row:** FMCB 1.93 and newer pass the Browser request on when **Go to Browser** (FMCB Configurator > Configure OSDSYS options; `OSDSYS_Inner_Browser` in `FREEMCB.CNF`) is AUTO or Force ON, so with those values **PS2 system browser** now lets FMCB load and the Browser opens with FMCB's menu behind it. With Force OFF (every 1.9x installer's default) or no value, FMCB drops the request, so the card update is still skipped. The file is read as FMCB reads it (comment lines skipped, the last entry wins, a USB drive's `mass0:/FREEMCB.CNF` before the card's `SYS-CONF` copy) and never written. **Tools > System > OSDSYS (skip card update)** starts the console's own OSDSYS menu without the card update (ROMs older than v5 ignore that and run it); **OSDSYS** still runs it. Same check as RiptOPL. Host test `tests/test_ps2browser_card_update.py`. NOT TESTED on PCSX2 or a real PS2.
- **SMB shares accept a Windows-style address:** a share `URL` written as `\\192.168.1.5\games` (or `\\192.168.1.5:1445\games`) in `SMB2.CNF` or the shares in `LAUNCHSTATION.CNF` is now read as `smb://192.168.1.5/games` (or `smb://192.168.1.5:1445/games`, port kept), so a path copied from Windows Explorer works. The usual checks still run on the result, and `smb://` URLs, the share editor and the config template are unchanged. Host test `tests/test_smb_shares.py`. NOT TESTED on hardware.
- **SMB server answers more file questions, and its screen runs at full speed:** the memory card SMB server now answers the stream list (one `::$DATA` stream per file), FileStatInformation and FileStatLxInformation, and the volume's sector size (512 bytes); a request for a file's 8.3 name gets "not found", as on NTFS with short names off. Windows 11 asks for the stream list, the 8.3 name and the sector size; it does not send the two stat queries over SMB, so those are for other clients. Folders still answer the stream list with "not supported". The **SMB server** screen slept 100 ms after every frame, so it drew at about 8 frames a second; it now draws every frame and still asks the server for its status about ten times a second. Host-tested and PCSX2-tested (60 FPS with a client connected); NOT TESTED on hardware.
- **USB wait pop-up keeps one steady line:** while Launchstation waits for USB storage, the pop-up flickered between "Checking USB root usb0:/", "USB root usb1:/ returned -19" and the waiting line, and the progress bar disappeared on each probe. After the first try it now shows "Waiting for USB storage... (attempt 2/4)" (then 3/4, 4/4) and keeps the bar while it probes again. The first try still shows "Checking USB media...". NOT TESTED on hardware.
- **Updater says what it is doing and needs less space:** the update pop-up now names each step (downloading from GitHub, checking the SHA-256, unpacking and checking the new ELF, adding missing bundled files, replacing the ELF). When there is enough free memory the package is downloaded into RAM and unpacked from there, so no `.PACKAGE` file is written to the card. Before downloading, the updater checks the free space on the device Launchstation runs from and says how much it needs if there is not enough; the installed ELF is untouched. The old ELF is kept as `.BAK` only during the swap and deleted once the new one is in place, and a `.BAK` left by an older build is removed. A failed temperature reading no longer blanks the temperature on the clock line. From [R3Z3N (saildot4k)](https://github.com/saildot4k)'s fork. Host-tested; NOT TESTED on PCSX2 or a real PS2.
- **A click for every cursor move:** when scrolling at full speed (one move every 40 ms), every other cursor click was skipped, because the sound code also ignored clicks less than 45 ms apart. The controller's repeat speed already sets the pace, so each move now plays its click, still spread over six voices so clicks do not cut each other off. From [R3Z3N (saildot4k)](https://github.com/saildot4k)'s sound audit. Host test `tests/test_cursor_sound_ticks.py` (master plays 12 of 24). NOT TESTED on PCSX2 or a real PS2.
- **Your own OSDSYS program launches, from any device and any path length:** a program chosen for **OSDSYS** in Settings was started only as an encrypted memory card update, so a normal ELF there (for example on USB) did not start, and a path longer than about 36 characters overran a 40-byte buffer. It now launches like any file opened in the File Browser (plain ELF or KELF). Without an override, OSDSYS still runs the card's own system update as before. Launches from USB and the ATA drive also stop copying a path over itself when removing the slash after the device name. From [R3Z3N (saildot4k)](https://github.com/saildot4k)'s fork. Host-tested; NOT TESTED on PCSX2 or a real PS2.
- **NFS shares:** NFSv4.0 exports are a new kind of network share, saved with the SMB shares at the end of `LAUNCHSTATION.CNF` with an `nfs://<IP address>:2049/<export>` URL (Settings > Network > SMB shares, Server type **NFS**, with User ID and Group ID rows). Files lists **Network (NFS)** once one is saved, and `nfs:/<NAME>` opens each connected share, as `smb:/<NAME>` does. The new `nfsman` driver is built on [Ronnie Sahlberg (sahlberg)](https://github.com/sahlberg)'s [unfs4](https://github.com/sahlberg/unfs4) (BSD 2-Clause), needs no portmapper or MOUNT protocol, and keeps open files across a reconnect; About credits him for the SMB and NFS shares. Neutrino is not handed `nfs:` paths yet: launching an ISO from one says it is not supported. Host-tested against Linux's NFS server and browsed in PCSX2; NOT TESTED on a real PS2. See [NFS shares](https://nathanneurotic.github.io/Launchstation/nfs.html).
- **PS2 system browser on FMCB cards:** like LoadBOOTer, FMCB ignores the Browser request, so on an FMCB card the plain **PS2 system browser** row opened the FMCB menu. Launchstation now skips the card update for FMCB too (`SYS-CONF/FREEMCB.CNF` on the card OSDSYS uses, and OSDMenu's `SYS-CONF/OSDMENU.CNF` on neither card). Cards are only read. NOT TESTED on a real PS2.
- **Two USB drives no longer freeze Launchstation or go missing:** with two USB drives plugged in, the USB storage driver (`usbmass_bd`, the same one most PS2 apps use) sent commands to both drives from one shared block with no lock. When one drive was being read (for example the File Browser's "Reading folder" on `mass0:/`) while the other was still starting up, the second command overwrote the first, one drive got the other drive's command, and the read waited forever. A drive that failed during start-up could also spin forever and stall the whole IOP. Launchstation now embeds its own copy of the driver (`iop/usbmass_bd`, see `ORIGIN.md`) that sends one command at a time, waits at most about 10 s for a drive to become ready, and leaves out a drive that never does. The Ember handoff and the IGR helper use the same copy. Host test `tests/test_usbmass_two_drives.py` (the unpatched driver fails it). A second review added three more fixes, so the driver source is now identical to RiptOPL's: a short status reply is read again instead of being taken as success, a drive unplugged during start-up stops the start-up, and start-up fails cleanly if the driver cannot create its locks. NOT TESTED on PCSX2 or a real PS2.
- **PS2 system browser on LoadBOOTer cards:** LoadBOOTer, the card update the memory card exploit installer writes, ignores the Browser request and always runs `mc0:/BOOT/BOOT.ELF`, so **PS2 system browser** never reached the Browser on those cards. Launchstation now recognises LoadBOOTer by reading the card (nothing on it is written) and skips the card update for it; other card updates keep their menu as before. NOT TESTED on hardware.
- **One picture reset at boot ([#277](https://github.com/NathanNeurotic/Launchstation/issues/277)):** the TV lost and regained the picture one extra time on every boot, because the screen was set up twice. It is now set up once, double buffered, as [R3Z3N (saildot4k)](https://github.com/saildot4k)'s fork does. NOT TESTED on hardware.
- **Launchstation keeps its own settings file ([#346](https://github.com/NathanNeurotic/Launchstation/issues/346), reported by [Windows10User2](https://github.com/Windows10User2)):** classic settings are now saved to `LAUNCHSTATION.CNF` instead of `LAUNCHELF.CNF`, which other wLaunchELF builds also read. With a built-in language picked, Launchstation saved translated launch-key names there that other builds could not read, so their menu entries said "is Not Found". `LAUNCHSTATION.CNF` is searched for in the same places; only when none exists is an old `LAUNCHELF.CNF` imported, read-only, and the next Save writes `LAUNCHSTATION.CNF` to the same folder when it can (otherwise to a memory card `SYS-CONF` folder or the ELF's folder). Nothing writes `LAUNCHELF.CNF` any more. NOT TESTED on hardware.
- **No hangs after 71 minutes switched on:** the internal timer wrapped after about 71.6 minutes of uptime, so a wait started after that (USB drive detection, device waits, pop-up deadlines and others) could hang for up to another 71 minutes. The timer now uses the console's 64-bit clock, which does not wrap. Host-tested; NOT TESTED on hardware.
- **MX4SIO driver from RiptOPL:** Launchstation now embeds RiptOPL's MX4SIO driver instead of the SDK copy. The SDK copy restarted a partial transfer from its first sector, counted a rejected write sector as written, left the caller's data bit-reversed after a write, and crashed the IOP on a buffer that was not word aligned. NOT TESTED on hardware.
- **Progress pop-up keeps moving during long device pauses:** the USB media probe, USB discovery, MMCE card switches and the Neutrino MMCE game ID wait now keep the progress pop-up drawn while they wait, instead of freezing it. Idea from [R3Z3N (saildot4k)](https://github.com/saildot4k)'s async graphics work. NOT TESTED on hardware.
- **SMB server for the memory cards:** **Tools > SMB server (memory cards)** shares `mc0` and `mc1` with a PC as `\\<PS2 IP>\mc0` and `\\<PS2 IP>\mc1`, over signed SMB2/SMB3 only, at most two clients, with the login shown on screen (`ps2`/`ps2` unless changed in Settings > Network). Built on [Ronnie Sahlberg](https://github.com/sahlberg)'s [libsmb2](https://github.com/sahlberg/libsmb2). Use it only on a network you trust. Host-tested; NOT TESTED on hardware.
- **SMB settings live in Launchstation's own file, as one SMB device, with a changeable server login:** saved SMB shares are now kept at the end of `LAUNCHSTATION.CNF` (after a `# SMB shares` line) instead of a separate `SMB2.CNF`. An old `SMB2.CNF` is still read until you first save a share, which copies its shares across; Launchstation never writes `SMB2.CNF`, which other launchers also read. Files shows one **Network (SMB)** device: an SMB1 share is a folder in it, named by its share name, and Back from it returns to `smb:/`. **Settings > Network** has **SMB server user name** and **SMB server password** for Tools > SMB server (memory cards), `ps2`/`ps2` by default, used from the next Start. NOT TESTED on hardware.
- **PS2 system browser keeps your FMCB or OSDMenu menu ([#336](https://github.com/NathanNeurotic/Launchstation/issues/336), reported by [Windows10User2](https://github.com/Windows10User2)):** since build 1132 the Browser opened without the memory card system update, so Circle showed the console's two-item menu until a restart. **Tools > System > PS2 system browser** asks for the Browser alone again, as wLaunchELF and PS2BBL do, so the card's menu loads first. A new **PS2 system browser (skip card update)** row keeps the 1132 route for a card whose update ignores the Browser request (it then opens that card's menu instead). NOT TESTED on a real PS2: PCSX2 cannot run a signed memory card update.
- **System settings tidied, with ideas from [R3Z3N](https://github.com/saildot4k)'s fork and Berion:** **Set PS2 Clock** is now one row that opens a popup with Set manually, Sync from Internet (Ethernet builds), Set software clock and Use PS2 hardware clock. Rows Launchstation shares with R3Z3N's System page now use his order, and the rows only Launchstation has follow them. The clock and save-location rows use clock and floppy icons. The Network page keeps its Sync PS2 clock row.
- **Neutrino launch options:** **Run game** is now the top row, so Confirm starts the game straight away. The per-game save row uses the floppy icon, and the menu sounds recover if preparing the ISO restarted the IOP.
- **Convert several saves at once:** with save files marked in the File Browser, **Convert to .psu, .psv, .cbs or .zip...** (PS2 save files) and **Convert to .mcs, .psv, .psx or raw...** (PS1 save files, or saves marked on a real PS1 card) now ask the format once and write one file per save, each read back, showing the save being written and "Completed items: 2 / 5" with a progress bar, then one summary, as [R3Z3N (saildot4k)](https://github.com/saildot4k)'s fork does with several copied saves. Files land next to the sources, or in one folder you pick when the sources are on a memory card. No file is replaced (a `.psu`, `.cbs`, `.zip`, `.mcs` or `.psx` takes the next free `-2` name; a PS3 `.psv` or raw name is never reused); a save that fails is counted and the rest still go. PS2 save folders on a real PS2 card still go through **Create PSU** first.
- **MMCE folder listings end cleanly and no longer come back empty:** the MMCE driver (mmceman) reported the end of every MMCE folder listing as a read error (-1) instead of "no more entries" (0), and for each entry it returned the card's internal handle number, which is 0 (read as "end of folder") when the card's first handle was free while the folder was open, so such a listing stopped before its first entry. Each entry now returns 1 and the end of a listing returns 0; bus timeouts and garbled replies still return -1. Same change as [ps2-mmce/mmceman pull request #11](https://github.com/ps2-mmce/mmceman/pull/11) by [AKuHAK](https://github.com/AKuHAK) (still open upstream); its status-query half was already in Launchstation. The driver code grows 32 bytes (measured on the object file). Host test `tests/test_mmce_dread_returns.py` runs the real `mmce_fs_dread` over a scripted card. NOT TESTED on PCSX2 or a real PS2.
- **Full kit ships Okeanos' UDPFS Assault 1.0.1 and the current i.LINK driver:** the kit's `POPS/` pins moved from RiptOPL `a2821278` to `4832d22c`, so `usbd.irx.udpfs` is the 61,949-byte UDPFS Assault 1.0.1 (it was the 51,029-byte TEST build), `usbhdfsd.irx.ilink` is the 27,769-byte fixed i.LINK driver (it was 27,129 bytes), and `POPS/UDPFS-NOTICES/` gains Okeanos' `PATHMAP.INI` example and updated notices. Every file is still SHA-256 pinned and the kit build fails on a mismatch. Checked only by the synthetic kit-packaging test and a pinned-externals fetch; no kit build with the real Neutrino download was verified here, and nothing was run on a PS2.
- **Circle respects a hidden HOME tab ([#343](https://github.com/NathanNeurotic/Launchstation/issues/343), reported by [Zack](https://github.com/zackcage6)):** with the Home tab switched off, Circle on Settings or at the top of the Files tab still jumped to HOME, and the hint still said "Home". Circle now goes to the first tab still enabled, and the hint names that tab (or is left out when you are already on it). No change with HOME on. NOT TESTED on PCSX2 or a real PS2.
- **Neutrino over i.LINK in the full kit:** `LAUNCHSTATION-<build>.zip` now replaces the upstream Neutrino's `modules/iLinkman.irx` and `modules/IEEE1394_bd_mini.irx` with RiptOPL's fixed builds (`ship/neutrino-ilink/`, from RiptOPL v1.2.0-Beta-4235 at `7128450`), as RiptOPL's own release kit already does. The stock driver tries the login only about 0.8 s after Neutrino's IOP reset while the drive still holds the menu's old login, so the game never saw the disk; the fixed one retries for up to 5 s. Their provenance and AFL-2.0 licence ship beside them as `neutrino/ILINK-README.txt` and `neutrino/ILINK-LICENSE.txt`. The packager pins both modules by SHA-256 and refuses a kit without them. Kit about 8 KB larger; on the card the two modules are 5,480 bytes larger and the two notices add 10,661 bytes. The ELF and the app ZIP/PSU are unchanged. Host test `tests/test_kit_package.py`; NOT TESTED on PCSX2 or a real PS2.
- **Launchstation icon in the memory card browser, made by the ELF ([#287](https://github.com/NathanNeurotic/Launchstation/issues/287), [#301](https://github.com/NathanNeurotic/Launchstation/issues/301), asked for by [Zack](https://github.com/zackcage6)):** the ELF now carries the `icon.sys` and icon the release ZIP/PSU ship in `res/memory-card/`, and when settings are saved it writes `icon.sys`, `list.icn`, `copy.icn` and `del.icn` into the `mc0:/` or `mc1:/` folder it runs from, as RiptOPL does. Copying only the ELF to a card folder (for example `mc0:/LAUNCHSTATION/`) is enough to get the icon. Only a top-level card folder is stamped, never the card root, a folder inside `APPS`, or `SYS-CONF`. A folder that already has a complete `icon.sys`, or one the card will not let it read or measure, keeps its own icon. `icon.sys` is written last, so a card that fills up part-way is retried on the next save. About 16 KB larger ELF. Host test `tests/test_mc_folder_icon.py` runs the real code against a mocked card. NOT TESTED on PCSX2 or a real PS2.
- **Mixed-format saves straight onto a memory card:** with save files marked in the File Browser (`.psu`, `.max`, `.cbs`, `.sps`, `.xps`, `.psv`, `.mcm` or Blaze `MCM` files, mixed), **Extract to mc0:/** and **Extract to mc1:/** now write them onto the PS2 card in that slot, as [R3Z3N (saildot4k)](https://github.com/saildot4k)'s Launchstation fork can. Each save becomes a new folder; every file is written, read back, and given the save's own mode and times, the same way a `.psu` restore does. A save already on the card by name, or one that does not fit, is skipped; one that fails part way is removed again. A selection of only `.psu` files keeps the existing PSU restore. Host-tested; NOT TESTED in PCSX2 or on a real PS2.
- **Hex Editor (Apollo Save Tool parity):** File Browser > Triangle > **Open in Hex Editor** on any file up to 512 KB (`.elf`, `.icn` and `.sys` included) shows offset, hex and text, 8 bytes per row. Confirm changes the byte under the cursor (Up/Down 1, R1/L1 16); a USB keyboard types hex digits; Triangle > **Go to offset...** jumps. It only overwrites bytes: no insert, delete or undo. Save writes the whole file, reads it back and compares it before it says *Saved and checked*; if that fails it says the file may be partly changed. Like the File Browser, it writes to `host:` and `udpfs:` only when host writing is on in the Network settings (the Text Editor now checks this too). It lives in the Text Editor's source and shares its file loading, font and layout. Host test `tests/test_hex_editor.py` compiles the real editor and its file IO and edits real files with scripted buttons. NOT TESTED on PCSX2 or a real PS2.
- **Export PS2 saves as .zip:** **Card contents > Export** and **Convert to...** now also write a `.zip` holding the save folder and its files, for a PC (Apollo Save Tool's zip export). Entries are stored, not compressed, so no compressor is linked; CRC-32 uses a 64-byte table instead of zlib's 8 KB. The folder's and files' modified times become the zip's times; card attributes are not kept, so use `.psu` to move a save between cards. Host-tested with Python's `zipfile` (CRCs, names, data, times); NOT TESTED on hardware.
- **Export PS2 saves as CodeBreaker `.cbs`:** **Card contents > Export** and the File Browser's **Convert to...** now also write a `.cbs` (as Apollo Save Tool does), named after the save folder. Export asks before replacing a file; Convert never replaces one and takes the next free name (`-2` suffix). The zlib stream is written as stored (uncompressed) blocks, so Launchstation links no compressor and a `.cbs` is about the size of the save; every zlib reader opens it. Export reads the written file back and compares its bytes; Convert also reads it back as a save and must get the same save. Reading a `.cbs` now takes the folder mode from offset 0x48, where Apollo and Cheat Device keep it (0x4C as before when 0x48 holds none). Part of the Apollo Save Tool parity goal. Host-tested against an independent Python reader; NOT TESTED on hardware, and no file was loaded in CodeBreaker.
- **Convert a PS1 save without a card image:** the File Browser's new **Convert to .mcs, .psv, .psx or raw...** turns one PS1 save file (`.mcs`, `.ps1`, `.mcb`, `.pda`, `.psx`) into another of those formats or a signed PS3 `.psv`, with the same code and the same bytes as **Card contents > Export**, as wLaunchELF_R3Z can from a file. **Convert...** on a PS1 `.psv` now goes the same way instead of saying to use a card image. On a real PS1 card in `mc0:/` or `mc1:/`, where each save shows as a raw file, the row exports that save to a folder you pick (Apollo Save Tool's export from a PS1 card). The original is only read and each file is read back. Host-tested; NOT TESTED on hardware, and the real PS1 card path is not tried on a console.
- **Import many save files of mixed formats at once:** mark save files in the File Browser (`.psu`, `.max`, `.cbs`, `.sps`, `.xps`, `.psv`, `.mcm` or Blaze `MCM` folder files, mixed) and **Import into a card image...** puts them all on one PS2 card image, like [R3Z3N (saildot4k)](https://github.com/saildot4k)'s **Extract saves...**. The card gets one verified safety copy first. A file that is not a PS2 save, a save already there by name, or one that does not fit is skipped, and the first one is named with the reason; any other error stops it, and the summary says how many were not tried. Each save is read back after it is written. For a real memory card, use **Extract to mc0:/** / **mc1:/** (see the entry above). Host-tested; NOT TESTED on hardware.
- **Export many saves at once:** **All saves here... > Marked saves...** now has **Export as .psu or .psv...**, which writes each marked save as a new file in one folder you pick (as Apollo Save Tool's export of all or selected saves). With nothing marked, it exports every save listed, and only the export is offered. A file already there by name is kept and counted, never replaced, so the same save on two cards is written once. A save that cannot be read is counted and the rest still go. The cards are only read. Each file is written with the verified write single exports use. Part of the Apollo Save Tool parity goal. Host-tested; NOT TESTED on hardware.
- **RetroArch `.srm` PS1 cards in Card contents:** a 128 KB `.srm` (the raw card RetroArch's PS1 cores save) now gets **Card contents...** in the File Browser and opens the PS1 view like a `.mcr`. It is checked by content: besides the `MC` start, the header and all 15 directory frames must carry their check bytes, and a file that fails those checks (such as another core's SNES or GBA `.srm`, even one of 128 KB that starts `MC` by chance) is refused as not a PS1 card and never written. The rest of the card data is not checked. Part of the Apollo Save Tool parity goal. Host-tested; NOT TESTED on hardware.
- **A PS1 card from several saves in one step (from [R3Z3N (saildot4k)](https://github.com/saildot4k)'s [wLaunchELF_R3Z](https://github.com/saildot4k/wLaunchELF_R3Z) "Create archive"):** mark PS1 save files in the File Browser (`.mcs`, `.psv`, `.psx`, `.ps1`, `.mcb`, `.pda` or raw saves) and **PS1 card from these saves...** makes one card holding all of them: Ember's `MC1.vmc`/`MC2.vmc`, POPStarter's `SLOT0.VMC`/`SLOT1.VMC` (exact names, never replaced), a plain `PS1-Saves.mcd`, a PS3 `.VM1` or a `.gme`, `.vgs`, `.vmp` or `.mcx` card, then opens it in Card contents. Every save is read and placed in memory first, so one that cannot be read, a name used twice, or more than 15 blocks stops it before any file is made; the card is read back and compared before it is kept, and the source saves are not changed. Uses the same reader and card writer as **Import save...**. Host-tested; NOT TESTED on hardware.
- **Hide tabs from Settings, and the HOME console line from themes:** Settings > Home & applications now has **Home tab**, **Files tab** and **Tools tab** (On/Off) for the `Dash_Disabled_Tabs` key added earlier, which had no menu row ([#278](https://github.com/NathanNeurotic/Launchstation/issues/278)). Settings has no row, and editing these rows always clears the Settings bit, so the menu cannot hide its own way back. The console model, ROM and region line stays at the top of HOME and stays on; a theme can turn it off with the new `console_info = 0` key, or from Customize theme > Tiles & menus > **Console info on HOME** ([#293](https://github.com/NathanNeurotic/Launchstation/issues/293)). Themes without the key keep the line.
- **Network start fixed (FTP, `host:`, netfs, `smb:`/`smb1:`, cloud and clock sync):** the PS2IP that Launchstation embeds is the SDK's NETMAN build (`ps2ip-nm`), but NETMAN was never loaded and SMAP was the PS2IP build, so PS2IP could not link and every network feature stopped at "PS2IP did not start" / "The network stack could not be started" (the #309 tester report). The start-up now loads NETMAN, then the NETMAN SMAP with no arguments, then PS2IP with the `IPCONFIG.DAT` address, the order [R3Z3N (saildot4k)](https://github.com/saildot4k)'s [wLaunchELF_R3Z](https://github.com/saildot4k/wLaunchELF_R3Z) PR 63 by [Ronnie Sahlberg](https://github.com/sahlberg) uses. A NETMAN failure names its own stage. The PS2SDK v1.0 DEV9 fallback keeps its own PS2IP and SMAP's PS2IP build, unchanged. IOP reset clears the NETMAN flag with the rest. Host test `tests/test_network_load_result.py` checks the order on both paths. NOT TESTED on PCSX2 or a real PS2.

Up to 64 cards (from up to 256 folders) and 1000 saves are listed, including more than 250 saves from one card. **Square** marks saves (a check replaces the icon), and the **Marked saves...** row at the top copies, moves or deletes all of them at once: each card that changes gets one safety copy for the whole batch, not one per save; saves already on the target card by name, or that do not fit, are skipped and counted; a failure stops the batch and says how many were not tried; Move and Delete are off when a marked save is on a read-only PCSX2 `.ps2` card. Backing out keeps the marks. Long dialog lists now also page with **L1**/**R1**. Part of #232; pending hardware validation.
- **Split a card into Game ID cards (Card contents):** **Split into Game ID cards...** makes one card per game from a card's saves, in the `<ID>/<ID>-1.mcd` layout that sd2psXtd-style MMCE devices pick when that game starts (`SLUS-21050/SLUS-21050-1.mcd`). The Game ID comes from each save folder's name (`BASLUS-21050...` gives `SLUS-21050`); system folders, PS1 saves and other names stay out and are counted in the result. Each card gets the source card's identity, starts at 8 MB and moves up a size only if the game's saves do not fit, and is built as `<ID>-1.mcd.PART`: only once it reads back with exactly that game's saves is it renamed (or, where the device cannot rename, copied with verification, removing the `.PART` only afterwards) to its final name, so an interrupted split never leaves a half-filled card that looks finished. A game folder that still holds a `.PART` is treated as unfinished, never reused, and named in the result. The source card is only read, and a game that already has a card in the output folder is skipped, never replaced. Results go to `mmceN:/WLE-GameID/<card>/` on MMCE and to `<card>-GameID/` next to the card elsewhere, so two cards holding the same game do not collide. The new **Install as MMCE Game ID card...** action (shown for images named `<ID>-1.mcd`) installs one into `MemoryCards/PS2/<ID>/` with the same verified publish as **Install as NEW selectable MMCE card**, and only when the adapter has no folder for that game yet. Failure messages now say when a partial file could not be removed, instead of always reporting it removed (also for New blank card and Copy to a new card of another size). Part of #232; pending hardware validation, including that the adapter picks these cards up as described. A card is named after the serial in the save folder's name; a game that saves under a different serial than it boots from is not matched by the adapter.
- **New blank card (File Browser):** in a USB, HDD, MMCE or network folder, **New blank card...** makes an empty 8, 16, 32 or 64 MB PS2 card image (`Blank-8MB.mcd` and so on). It is formatted with the PS2's standard layout and timestamped from the console clock, then reopened and checked: right size, no saves, every cluster but the root free. Otherwise the file is removed. It only ever creates a new file; on MMCE it goes to `mmceN:/WLE-New/`, outside `MemoryCards/`, ready for **Install as NEW selectable MMCE card**. Memory cards and VMCs cannot hold a card image, so the action is not offered there. **Install as NEW selectable MMCE card** now accepts images in `mmceN:/WLE-New/` and `mmceN:/WLE-Resized/`; before, it refused the resized cards it was recommended for. Part of #232; pending hardware validation, including whether the sd2psx and the PS2 accept the 16 to 64 MB layouts.
- **Input and scrolling:** hold-to-repeat Type/Delete without repeating menu actions; filename prompts show the destination and filter unsuitable characters; lists share centered scrolling. Adapted from [saildot4k](https://github.com/saildot4k); hardware validation pending.

- **Video and sound safety:** video-mode changes require confirmation within 10 seconds or restore the previous mode and offsets. Sound-effect fallback excludes the music voice. Adapted from [saildot4k](https://github.com/saildot4k); hardware validation pending.
- **Card rename boundaries:** PS2 card names are limited to 31 bytes to prevent receiver truncation and duplicate names; PS1 retains its 20-byte limit. Socket option lengths and optional receive-address outputs are checked locally, and TLS trust errors identify the active CA store.

- **Copy a card to a new size (Card contents):** **Copy to a new card of another size...** makes a new 8, 16, 32 or 64 MB card image holding every save of the current one, which is only read. The new image keeps the source's format identity and gets the PS2's standard layout for its size; every save is copied and read back, and the finished card must list exactly the source's saves, or the new file is removed. It never overwrites a file; MMCE results go to `mmceN:/WLE-Resized/`, outside `MemoryCards/`, ready for **Install as NEW selectable MMCE card**. Pending hardware validation, including whether the sd2psx and the PS2 accept the 16 to 64 MB layouts.
- **Which MMCE card is in use, and switching cards (File Browser):** in an MMCE folder, **Which MMCE card is in use?** asks the device (card and channel) and then confirms the answer by content, because the device can keep reporting the old number after its buttons were used; BootCard and Game ID cards are found by content. On a numbered card (`MemoryCards/PS2/CardN/CardN-C.mcd`), **Make this the active MMCE card...** selects it, waits up to 15 s while the device is busy, and reports success only when number, channel and content all agree. The same check now guards every card write: a card the device reports as selected, serves, or might be serving is never written. Pending hardware validation.
- **Card contents (File Browser):** a new **Card contents...** action on `.mcd`, `.ps2`, `.bin`, `.vmc` and `.mc2` card images lists the saves inside, with their titles, file counts and sizes, and the card's free space. A save can be copied or moved to another card image, deleted, or exported as `.psu`, and a `.psu` can be imported. Before any write the whole target card is copied to a `WLE-Safety` folder (beside the image, or `mmceN:/WLE-Safety/` for MMCE cards) and the copy is verified; the newest ten per card are kept. A card the MMCE device is serving to the console right now is never written, and when Launchstation cannot tell which card that is, it writes to none. Nothing is written while a VMC is mounted as `vmc0:` or `vmc1:`, because the VMC driver keeps its own copy of the card's tables; unmount it first. Cards with more than 250 saves list the first 250, still take copies and imports (duplicate names are checked against every save), and cannot be copied to a new size. A move removes the save from the first card only after it reads back correctly on the second. The writer underneath (`src/mc_card_write.c`) writes data and folder first, then the FAT, then publishes the change with one 512-byte page, and reads every change back; host tests cut the power before every write and check that the card still opens and no other save changed. PCSX2 `.ps2` cards and saves with sub-folders are read-only here. Pending hardware validation.
- **Faster IGR card backup:** the automatic MMCE backup after IGR now decides whether a card changed from a fingerprint of its filesystem index (folders, file sizes, dates, locations: a few hundred KB) instead of reading the whole card and its newest history copy byte for byte. Each history copy gets a small `<copy>.FP` file holding that fingerprint; old history without one is compared in full once and then gets one. The `B?DATA-SYSTEM` folder's contents are left out, because the PS2 and OPL rewrite its history file when a game starts, which used to make every played card look changed. The fingerprint cannot see a save rewritten in place at the same size while the console clock is stuck or reset at boot (its date does not change), so a match is trusted for at most 8 backups in a row; the next one compares every byte and restarts the count. The **Back up all MMCE cards** actions in Tools and the File Browser still compare every byte, and also catch raw-page writes the fingerprint cannot see. Pending hardware validation.
- **MMCE driver:** a file or folder close that timed out or got a bad reply no longer keeps its handle slot, so repeated failures can no longer use up all 16 slots and make every MMCE open fail until reboot. Opening a file or folder the card reports as missing now returns "not found" (`-ENOENT`) instead of a generic error. Ported from RiptOPL's mmceman; pending hardware validation.
- **Build system:** the legacy Makefile build, the prebuilt SDK-duplicate IOP modules and the legacy libcdvd were removed; PS2BUILD (`ps2.yaml`) is the only build path.
- **Release downloads:** the `latest` release now also offers the packed ELFs on their own: `LAUNCHSTATION.ELF`, `LAUNCHSTATION-DS.ELF`, and `BOOT.ELF` / `BOOT2.ELF` (identical copies of the standard ELF). Publishing also refreshes the release page date.
- **Footer hints (#221):** hint labels are now always drawn whole, never cut to "Op...", "Sele..." or "...". The bar spreads its gaps dynamically (24 px down to 10 px), then shrinks the label type if it is still too wide; it no longer goes through the ellipsizing text-fit step, so a measuring/fitting mismatch cannot clip a label. The SELECT **Launch keys** panel is wider as well.
- **Edit metadata:** now opens the OPL-format `title.cfg` beside the ELF (creating a starter with `title=` and `boot=` if missing) instead of creating a separate `<ELFNAME>.cfg`; an existing `<ELFNAME>.cfg` is still read. Paths like `host:APP.ELF` (no slash) now resolve to their folder. Thanks [saildot4k](https://github.com/saildot4k).
- **Recent applications:** launching a game image (`.iso`, `.bin`, `.cue`, `.vcd`) no longer adds it to Recent or rewrites the shared list file. Thanks [saildot4k](https://github.com/saildot4k).
- **Dashboard menu:** removed the duplicate **File Browser** entry; the Files tab is one L1/R1 away.

- **Release packages:** both app variants and the full kit now include `APPINFO.PBT` with per-variant Launchstation metadata, plus the memory-card icon set (`icon.sys`, `list.icn`, `copy.icn`, `del.icn`) beside the ELF in every ZIP and PSU.
- **Launch options:** application options gain **Start at boot** / **Don't start at boot**, which sets the existing automatic-start target from the library (the startup banner and any-button cancel are unchanged). Holding the confirm button while an application launches does the opposite of **Reset IOP before launch** for that one launch; the options menu shows the hint.
- **Video mode on shared memory cards:** a saved 576p that the current console cannot drive now boots in Auto but stays saved (it used to be overwritten with Auto), so the setting applies again when the card returns to a supporting console. Unsupported modes remain greyed out in Settings.
- **Sound theme (#160):** Settings > Sound > *Sound theme* switches between the original effects (Classic, default) and a new PS2-style set of original synthesized tones (soft glassy blips, a single-sweep L1/R1 hop, an ambient boot swell). Switching reloads the effects live. Regenerate the set with `python3 scripts/gen_sfx.py`.
- **Sound:** sound now uses the PS2BUILD SDK `audio` driver and `audsrv-compat` client; the vendored audsrv EE client and prebuilt audsrv package were removed.
- **Build toolchain:** release ELFs are now built with the PS2BUILD LLVM/Clang toolchain (EE and IOP). Mbed TLS and libjpeg-turbo are built from source with the same toolchain, and CI fails if a release ELF contains non-Clang objects. `PS2BUILD_TOOLCHAIN=gcc` remains available for comparison builds.
